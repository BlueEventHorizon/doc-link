# DES-003 論理データモデル

**状態**: Draft 0.1・未承認\
**更新日**: 2026-10-20\
**根拠**: [ToC の情報要件](../requirement/REQ-003-toc.md#sec-7)、[設計書の構成](README.md)

## 1. モデルの境界

このモデルは情報の同一性、関係、版、一次情報源を定義し、物理スキーマを指定しない（保存方式は SQLite、[DES-002 §4](DES-002-execution-responsibilities.md)）。「現在の現物」「最後に確定した索引」「変更影響候補の報告まで処理済みの比較基準」は別の情報である。キー所属は参照先の有効性を制限しない。

文書情報は `doc_link_id` ごとに一つの行として一か所に保存し、キー別に複写しない（決定: 旧 R-001）。複数キーから同じ行を参照するため、一つの検索結果で異なる版のフィールドが混在することはない。ToC の確定版が表すのはキー別の索引状態（所属、参照関係、反映済みハッシュ、検査結果）であり、文書情報行を含まない。文書情報行は文書単位で確定し、ToC が古い版のキーからも最新が見える（決定: 旧 R-004、要件 D-024）。

## 3. 多重度と範囲

- 一つの管理キーは、指定された時点の対象集合として複数の文書 ID を持つ。一つの文書 ID は複数キーに所属できる。所属はキーごとの対象走査によって確定する。
- 一つの文書は複数の参照記述を持てる。参照先 ID は管理対象外でもよく、参照先が索引にないことと、指定ディレクトリ内に実体がないことは別である。
- 逆参照は、走査して登録した参照元から得られる派生情報である。世界中のすべての参照元の一覧ではない。
- 一つのキーには現在公開する ToC の確定版が高々一つある。初回構築前はゼロである。候補版は公開版ではない。
- セクション単位の情報は、要件 U-006 の識別方法が確定した場合にだけ安定した識別を持つ。現段階で見出し文字列を恒久 ID として扱わない。

## 4. 値の意味と鮮度

文書 ID と本文ハッシュは異なる。ID は発行時に固定され、本文ハッシュは観測した内容に応じて変わる。本文の変更検出用比較値と、参照記述（特に物理パス）の比較値は分ける。リンク先の物理パスだけを直したとき、本文変更として報告するかどうかは、要件 U-007 の正規化規則に従う。

参照検査結果の「一致」は、記録されたディレクトリと検査時点についてのみ成立する。検索時点での現在の正しさを主張するには再走査が必要である。対象文書の鮮度と参照先の鮮度は独立した属性として扱う。

管理対象から離脱した文書は、指定キーの確定版から除く。対象範囲の外へ実体を探しに行かず、削除と範囲外への移動を区別しない。ただし、残存する参照記述の検査は、その記載パスが指定するディレクトリの走査結果で決める。

## 5. 未決の関係

現時点で未決の関係はない。文書 ID の発行方式と一意性の範囲は要件 D-028／D-030 で決定した（旧 R-007、要件 U-016）。
