# DES-006 文書検索設計

**状態**: Draft 0.1・関連度判定方式は未決\
**更新日**: 2026-09-29\
**根拠**: [文書検索要件](../requirement/REQ-004-search.md)

## 1. 検索前の判定

検索要求はキー（省略時は予約キー `all`）とタスク・検索条件を持つ。指定キーの確定済み ToC がなければ、検索せず初回構築が必要と返す。確定版があれば、その版に保存した再解釈可能な対象指定で現在の一覧を走査し、ID、パス、比較値を版と照合する。新しい完全な対象指定が同時に与えられた場合はそれを優先する。対象指定の展開・現物の読取りが失敗した場合は「更新不要」と判定しない。

検索前検査の結果は「再構築不要」「再構築必要」「判定不能」を区別する。比較で再構築不要なら確定版を検索する。再構築が必要なら Skill がユーザーへ「再構築後に検索」「既存版のまま検索」の二択を確認する。前者は [DES-005](DES-005-indexing.md) が正常確定した場合だけ新版を検索し、失敗時に旧版で黙って検索しない。後者は ToC と比較基準に書き込まず、結果に古い版であることを明示する。

対象指定の展開または現物の読取りに失敗した「判定不能」は、再構築不要・再構築必要のどちらにも読み替えない。検査不能の原因と使用可能な旧確定版の有無を返す。ここから旧版検索を利用者選択で許すか、検索を停止するかは要件確認待ちであり、未決のまま成功検索へ進まない。

## 2. 検索結果の契約

各候補は文書 ID、確定版に記録されたパス、関連理由、必要ならセクション、使用した管理キー・ToC 版・鮮度判定を持つ。「既存版のまま」を選んだ場合は、その版が現在の対象集合を反映していない可能性を結果全体にも付ける。文書が現物で移動・削除されていても、古い索引のパスを現在の実体パスとして断定しない。

script は確定版と入力キーに基づく候補取得・版情報の固定を担当する。自然言語タスクとの意味的な関連度を script の検索規則と AI のどちらで評価するか、その順位付けの仕様は未決である。AI を使う場合も、存在しない ID を補ったり、索引の版・パスを独断で訂正したりしない。

## 3. 参照情報の鮮度

ToC の対象文書が変わっていなくても、管理対象外の参照先だけが移動・消失し得る。保存済み参照検査は検査時点の結果であり、検索時点の「現在も正しい」の根拠にはしない。検索時に参照先を再走査するか、最終検査時点だけを提示するかは旧 R-003 として未決である。この決定に対応するまで、検索結果で参照の現在性を断定しない。
