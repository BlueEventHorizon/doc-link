# DES-006 文書検索設計

**状態**: Draft 0.1・関連度判定方式は未決\
**更新日**: 2026-10-15\
**根拠**: [文書検索要件](../requirement/REQ-004-search.md)

## 1. 検索前の判定

検索要求はキー（省略時は予約キー `all`）とタスク・検索条件を持つ。指定キーの確定済み ToC がなければ、検索せず初回構築が必要と返す。確定版があれば、その版に保存した再解釈可能な対象指定で現在の一覧を走査し、ID、パス、比較値を版と照合する。新しい完全な対象指定が同時に与えられた場合はそれを優先する。対象指定の展開・現物の読取りが失敗した場合は「更新不要」と判定しない。

検索前検査の結果は「再構築不要」「再構築必要」「判定不能」を区別する。比較で再構築不要なら確定版を検索する。再構築が必要なら Skill がユーザーへ「再構築後に検索」「既存版のまま検索」の二択を確認する。確認時には script が照合結果から数えた再構築の規模（新規・離脱・パス変更・内容変更・ID 発行の件数と、同じ内容ハッシュの文書情報行がなく AI 生成が必要な件数）を示す（要件 D-027）。参照先の走査結果と生成にかかる時間はこの時点では分からないため示さない。前者は [DES-005](DES-005-indexing.md) が正常確定した場合だけ新版を検索し、失敗時に旧版で黙って検索しない。後者は ToC と比較基準に書き込まず、結果に古い版であることを明示する。古い版から使うのはキー別の索引状態（所属、参照関係、反映済みハッシュ、検査結果）であり、文書情報は最新の行を表示する（要件 D-024）。検索はロックを取らず、確定済みの行を読む。

対象指定の展開または現物の読取りに失敗した「判定不能」は、再構築不要・再構築必要のどちらにも読み替えない。判定不能は障害として扱い、検索を停止して、判定できなかった対象と原因を返す。旧版での検索を利用者に提示しない（要件 D-026）。frontmatter の解析不能（ID 欠落扱い）や対象ディレクトリの消失（対象離脱）は判定不能ではなく、再構築必要に分類する。

## 2. 検索結果の契約

各候補は文書 ID、確定版に記録されたパス、関連理由、必要ならセクション、使用した管理キー・ToC 版・鮮度判定を持つ。「既存版のまま」を選んだ場合は、その版が現在の対象集合を反映していない可能性を結果全体にも付ける。文書が現物で移動・削除されていても、古い索引のパスを現在の実体パスとして断定しない。

script は確定版と入力キーに基づく候補取得・版情報の固定を担当する。自然言語タスクとの意味的な関連度を script の検索規則と AI のどちらで評価するか、その順位付けの仕様は未決である。AI を使う場合も、存在しない ID を補ったり、索引の版・パスを独断で訂正したりしない。

## 3. 参照情報の鮮度

ToC の対象文書が変わっていなくても、管理対象外の参照先だけが移動・消失し得る。保存済み参照検査は検査時点の結果であり、検索時点の「現在も正しい」の根拠にはしない。検索は、検索結果に現れた文書が持つ参照記述について、リンク定義の指定ディレクトリを再走査して現在の一致状態を確認する（決定: 旧 R-003）。走査対象は検索結果に現れた参照記述に限り、コーパス全体を走査しない。走査が失敗した場合は「検査不能」として返し、現在性を断定しない。
