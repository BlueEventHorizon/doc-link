# DES-008 Markdown 解析・比較値・生成情報の規則

**状態**: Draft 0.1・解析詳細の未決あり\
**更新日**: 2026-09-29\
**根拠**: [ID 要件](../requirement/REQ-002-document-id.md)、[ToC 要件](../requirement/REQ-003-toc.md)、[参照要件](../requirement/REQ-005-references.md)

## 1. 文書 ID の読取りと書込み

frontmatter の `doc_link_id` から、システム発行の `DLID-` 付き固定長 ID として認識できる単一文字列を読む。欠落・空・null・解析不能・認識不能はいずれも「文書 ID が存在しない」と分類し、形式不正という別分類を作らない。「文書 ID が存在しない」と判定した文書には ID 管理処理が発行・保存し、認識済みの発行済み ID を本文やパスから再計算しない。発行の種、方式、長さ、文字集合は U-001 の決定待ちであり、サンプル値を検証規則に転用しない。

既存 frontmatter と本文を保ち、書き込むのは `doc_link_id` の追加・置換だけとする。frontmatter の構文エラー、重複キー、書込み中断に対して、データを失わずどう診断・復旧するかは実装前に定める必要がある。

## 2. Markdown 参照と位置

標準リファレンスリンクの ID ラベルと対応する定義を解析し、ID・記載パス・参照元の位置を取得する。相対パスは参照元ファイルの配置を基準に解決する。参照先 ID と物理パスは別の値であり、片方の変更をもう片方へ自動伝播しない。未定義ラベル、重複定義、URL、フラグメント、エスケープ、大小文字の扱いはテスト可能な解析規則として実装前に確定する。セクション識別と記法は U-006 の決定待ちである。

## 3. 比較値とハッシュ

区別すべき入力は、文書 ID、相対パス、参照記述・リンク定義、本文の意味内容である。ID の発行値は内容比較値とは独立する。少なくとも ToC に反映した内容比較値、現在の現物から計算した比較値、変更影響候補の報告まで完了した処理済み比較基準を混同しない。物理パスだけの修正で本文変更の報告が連鎖しないようにする必要はあるが、どの構文要素を除外・正規化するかは U-007 の決定待ちである。現段階でハッシュ入力の正準化、方式、セクション境界を実装規則として固定しない。

決定後は、入力文字列から比較値までの再現可能なテストベクトルを作る。改行差、末尾空白、frontmatter、リンク定義のパス、リンクラベル、見出し、本文変更、セクションの追加・移動を別々に試す。意図しない意味変更を同一ハッシュとして扱う正規化は採用しない。

## 4. AI 生成フィールド

タイトルが機械取得できない場合の生成方法と、目的・内容概要・適用作業・キーワードの生成入力を定める。生成 AI に渡す上限はフィールド別の `L` のみとする。script の検証器は `H = floor(L × 1.3)` を用い、`L` 超・`H` 以下を受理し、`H` 超を拒否する。生成 AI が参照するプロンプト・ルール・再試行メッセージに `H` や余白の存在を含めない。数値の `L` は U-013、文字数の単位は U-014 の決定待ちである。検証器のエラーを生成 AI へ戻す場合も実際の拒否境界を開示しない。
