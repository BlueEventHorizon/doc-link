# doc-link 設計書の構成

**状態**: 設計中・未承認\
**更新日**: 2026-10-06

要件定義書は「実現する振る舞いと制約」の正本、ここにある設計書は「どの主体・情報・状態・処理で実現するか」の正本とする。要件と設計が食い違う場合、設計だけで要件を上書きしない。未決事項を解決するまで、該当する遷移や結果を確定仕様として扱わない。

| 文書                                                      | 担当する内容                                               |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| [DES-001 全体設計](DES-001-system-overview.md)            | システム境界、主要操作の接続、全体シーケンス、共通不変条件 |
| [DES-002 実行主体](DES-002-execution-responsibilities.md) | Skill・決定論的な script・各 AI の責務と書き込み権限       |
| [DES-003 データモデル](DES-003-data-model.md)             | 識別子、情報源、論理的な関係・版・鮮度                     |
| [DES-004 状態モデル](DES-004-state-machines.md)           | 独立した状態機械、許可遷移、禁止遷移、失敗・再実行         |
| [DES-005 ToC 構築](DES-005-indexing.md)                   | 対象確定、ID 保証、差分、情報取得、候補検査・確定          |
| [DES-006 文書検索](DES-006-search.md)                     | 検索前検査、利用者の選択、検索結果の鮮度                   |
| [DES-007 参照と変更通知](DES-007-references-impact.md)    | 参照検査、逆引き、変更影響候補の通知                       |
| [DES-008 内容規則](DES-008-content-rules.md)              | Markdown 解析、ID、ハッシュ、AI 生成結果の検証契約         |
| [DES-009 検証設計](DES-009-verification.md)               | 状態遷移と変換規則のテスト、要件との対応                   |

汎用的な執筆手順は[要件から設計への手順](../../rule/requirements_to_design.md)に置く。各図は理解用の表示であり、許可遷移の規範は DES-004 の遷移表とする。各処理の詳細は当該文書だけに置き、全体設計には重複して記載しない。

## 確定を妨げる判断待ち

- 関連情報を一つの確定済み版として公開する論理的な単位
- 参照先ディレクトリを走査できない場合の ToC 確定可否（要件 U-020）
- 要件で未決定のセクション識別、ハッシュ正規化、ID の一意性保証範囲など
- 検索前検査が判定不能な場合の利用者選択（要件確認待ち）

これらは保存方式（JSON/RDB）の選択より前に整理する。設計書の Draft 表記を外すには、全要件・受け入れ条件との対応、許可・禁止遷移の網羅、未決事項の決定とレビューが必要である。
