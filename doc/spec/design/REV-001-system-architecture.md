# doc-link システム設計の新規レビュー

**状態**: 草案レビュー・未解決\
**更新日**: 2026-09-28\
**対象**: [システム設計草案](DES-001-system-architecture-draft.md)と[現行要件定義書群](../requirement/REQ-001-overview.md)

## 判定

現時点で基本設計を確定できない。ディレクトリ走査を現在状態の根拠とする方針は明確だが、走査結果を確定する論理的な単位と、その後に検索してよいデータの鮮度・範囲がまだ定まっていない。JSON か RDB かの選択はブロッカーではない。以下は今回の設計方針を前提に、最初から点検し直した結果である。

## ブロッカー

### R-001 同一文書の複数キー間での状態

[REQ-003 §7](../requirement/REQ-003-toc.md#sec-7) は同じ ID の文書情報を論理的に一つとする。一方で、キー A の走査で更新した文書がキー B の ToC にも存在する場合、[指定していないキーを更新しない規則](../requirement/REQ-003-toc.md#sec-11)がある。このとき B の検索結果に新旧どちらの要約・パス・参照状態が見えるべきかが未定義である。JSON と RDB のどちらでも同じ問題が起こる。

**必要な判断**: B を古い確定済み状態として残すか、共有された新情報を即時に見せるかを定義する。どちらでも B の対象集合を走査していないことを隠してはならない。

### R-002 複数キーと処理済みハッシュの完了単位

[REQ-003 §7.5](../requirement/REQ-003-toc.md#sec-7-5) は文書 ID と処理済みハッシュを対応付ける一方、[REQ-003 §10.1.3](../requirement/REQ-003-toc.md#sec-10-1-3) は指定キーでの調査・通知やキーからの離脱を扱う。同じ文書が A と B に属する場合、A の影響調査完了だけで ID 単位の比較基準を進めると、B でまだ把握していない参照元への調査を済んだものと誤認し得る。

**必要な判断**: 影響調査を「文書の変更 × 調査済み参照元の範囲」で管理するか、全管理キーを対象に完了させてから ID 単位の比較基準を進めるかを定義する。

### R-003 参照先の変更だけでは検索前の更新要否を検出できない

[REQ-004 FR-006](../requirement/REQ-004-search.md#12-文書検索) は、保存した管理対象指定から現在の対象文書を列挙して ToC 再構築要否を判定する。しかし、参照先は[管理対象キーの外にも存在できる](../requirement/REQ-005-references.md#fr-007-文書-id-を使用した参照)。参照元が不変で参照先だけが移動・削除された場合、対象文書の比較だけでは古い参照検査結果に気づかず、そのまま ToC を検索し得る。

**必要な判断**: 検索前に参照先ディレクトリも走査して検査結果の鮮度を確認するか、参照検査結果を「最後に検査した時点の状態」として扱い、検索時に現在の正しさを主張しないかを定義する。現在の正しさを返す操作では実走査が必須。

### R-004 関連情報を一つの確定済み状態として公開する規則

[REQ-003 FR-004](../requirement/REQ-003-toc.md#sec-11) はキー別 ToC の一括確定を要求する。しかし、文書情報・キー所属・参照関係・検査結果の更新中に、それぞれ異なる版を検索が読み得るなら、論理的に一つの確定済み ToC とはいえない。これは単一 JSON ファイル、複数 JSON ファイル、RDB のいずれでも確認すべき条件である。

**必要な判断**: 公開可能な版の単位と、失敗後に最後の確定済み状態を維持・再実行する規則を定める。具体的な確定手段は保存方式を選ぶ後続設計で決めればよい。

## 重要な修正点

### R-005 参照先が指定ディレクトリ外へ移った場合

[REQ-005 FR-009](../requirement/REQ-005-references.md#fr-009-リファレンスリンクの検査) の走査で分かるのは指定ディレクトリ内の不在までであり、移動先は分からない。[REQ-005 AC-003](../requirement/REQ-005-references.md#ac-003-参照パス不一致の検出) の「文書移動後」は移動範囲を限定していない。移動先の通知は、同じ ID を実際に発見したときにだけ可能という [FR-010](../requirement/REQ-005-references.md#fr-010-参照パス修正情報の通知) の条件に合わせる必要がある。

### R-006 逆参照と影響調査の網羅範囲

[REQ-005 FR-013](../requirement/REQ-005-references.md#fr-013-変更影響の特定) が逆引きできるのは走査・登録された参照元だけである。全キー・管理対象外・未走査の文書まで含む完全な逆引きではない。調査結果には「どの管理対象指定・キー・走査時点に対して確認したか」を付ける必要がある。

### R-007 ID の発行時と検出時の一意性の範囲

[REQ-002 FR-001](../requirement/REQ-002-document-id.md#fr-001-文書-id-の発行と読み取り) は ID 発行前の重複検査を求めるが、参照先は管理対象外にも存在し、全世界を走査できない。発行時に検査できる範囲と、衝突確率を十分低くする発行方式を分けて定義する必要がある。これは既存の U-016 とも対応する。

## レビュー後の扱い

R-001〜R-004 は基本設計の決定前に解消する。R-005〜R-007 は同時に要件文言と受け入れ条件へ反映する。保存方式は要件で固定せず、論理的な完了単位と検索時の鮮度ポリシーを先に詰める。
