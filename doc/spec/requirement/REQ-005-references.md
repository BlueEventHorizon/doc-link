## 13. 文書参照とリンク検査

### FR-007 文書 ID を使用した参照

管理対象文書から別の文書を正式に参照する場合、文書 ID を含む規定の記法を使用すること。参照先が参照元と同じ管理キーに所属することや、doc-link の管理対象であることを参照の成立条件にしてはならない。

Markdown では、標準のリファレンスリンクを使用する。

```markdown
詳細は[アーキテクチャ原則][DLID-7K3M9P2X6T8V4R1Q]を参照する。

[DLID-7K3M9P2X6T8V4R1Q]: ../architecture/overview.md
```

この記法では、文書 ID が参照先の論理的な同一性を表し、リンク定義のパスが参照先として指定された物理的な配置を表す。パスが現在も正しいかは実際のディレクトリ検索で検査する。

文書 ID を含まないファイル名の記載や自然言語による言及を、正式な依存関係として扱うかは未決定とする。機械的な追跡可能性を保証するため、正式な依存関係には含めないことを推奨案とする。

### FR-009 リファレンスリンクの検査

プラグインは、Markdown リファレンスリンクについて、リンク定義のパスから参照先ディレクトリを特定し、実際にそのディレクトリを検索して少なくとも次を検査できること。保存済みの ToC やデータベースの登録有無だけを、現在の参照の正しさの根拠としてはならない。

- 参照ラベルに文書 ID が記載されている
- 指定されたディレクトリ内で、参照先文書 ID を持つファイルが見つかる
- リンク先パスが、その文書 ID を持つファイルの現在パスと一致する
- 相対パスが参照元文書から正しく解決できる

指定されたディレクトリの検索が正常に完了しても文書 ID が見つからない場合は、「指定されたディレクトリ内に参照先がない」と記録する。これは世界中にその文書が存在しないことを意味しない。ディレクトリを検索できない、または検索が完了しなかった場合は、存在・不在を断定せず「検査不能」と記録する。検査結果は検索の完了後に保存する。

### FR-010 参照パス修正情報の通知

文書の移動または改名によりリンク定義の物理パスだけが古くなった場合、プラグインは実際のディレクトリ検索で同じ文書 ID の現在パスを確認できたときに限り、参照元文書 ID、参照元パス、問題箇所、記載されている古いパスおよび確認済みの現在パスを、修正必要箇所としてプロジェクト管理 AI へ通知できること。現在パスを確認できない場合は、指定ディレクトリ内での不在または検査不能を通知し、保存済みデータから現在パスを推測して確定値として通知してはならない。

doc-link はリンク定義を更新しないこと。プロジェクト管理 AI がリンク定義を修正した後、doc-link は再検査によってパスの一致を確認できること。

<a id="sec-13-1"></a>

### 13.1 セクション参照

<a id="sec-13-1-1"></a>

#### 13.1.1 課題

Markdown の見出し文字列や自動生成アンカーだけでセクションを識別すると、見出し名の変更によって参照が壊れる。

文書 ID と同様に、パスや表示名から独立したセクション識別が必要かを検討する。

<a id="sec-13-1-2"></a>

#### 13.1.2 候補

#### 案 A: 見出し文字列から生成したアンカーを使う

- 既存 Markdown と親和性が高い
- 見出し名の変更に弱い
- Markdown 処理系によってアンカー生成規則が異なる可能性がある

#### 案 B: すべてのセクションに恒久的なセクション ID を付ける

- 追跡は強固になる
- 文書作成者の記述負担が大きい
- セクション分割・統合時の ID 管理規則が必要になる

#### 案 C: 外部から参照されるセクションだけに ID を付ける（推奨）

- 追跡が必要な箇所を安定して識別できる
- 全セクションへの ID 付与を避けられる
- 参照を追加する際に ID を付与する手順が必要になる

セクション参照の記法、セクション ID の形式および各案の採否は未決定とする。

## 14. 変更影響の調査と通知

### FR-013 変更影響の特定

文書またはセクションに意味のある変更があった場合、プラグインは管理対象文書から抽出済みの参照関係を逆引きし、把握している参照元文書を特定できること。

影響調査の候補には少なくとも次を含める。

- 変更された文書またはセクション
- 変更前後を識別するハッシュ情報
- 直接参照している文書
- 必要に応じて間接的に依存する文書
- AI による確認が必要な理由

### FR-014 doc-link による影響調査と通知

機械的に変更と参照元を特定した後、doc-link は必要に応じて影響調査担当 AI を使用し、変更箇所と参照元文書を読み、参照元文書の修正要否を調査できること。

判断結果を少なくとも次に分類できること。

- 修正不要
- 修正必要
- 人間の判断が必要
- 調査不能

影響調査結果には、少なくとも変更された文書 ID と箇所、影響候補となる参照元文書 ID と箇所、修正要否の判断、判断根拠、および必要な対応を含め、プロジェクト管理 AI へ通知すること。

参照関係が存在することだけを根拠として、修正が必要だと確定してはならない。修正が必要と判断した場合も、doc-link は参照元文書を変更せず、プロジェクト管理 AI が実際の修正を行うこと。

必要な影響調査とプロジェクト管理 AI への通知が正常に完了した対象について、[§10.1.3](REQ-003-toc.md#sec-10-1-3) に従い処理済みハッシュ一覧の比較基準を更新する。調査または通知が失敗した対象の比較基準は更新せず、次回も未処理として検出できること。

### FR-015 影響調査結果の管理

同じ変更に対する影響調査を不必要に繰り返さないため、次の情報を管理できることを要件候補とする。

- 調査対象となった変更のハッシュ
- 調査した参照元文書
- 調査日時
- 判断結果
- プロジェクト管理 AI から返された修正結果または対応結果
- 人間の判断が必要な場合の理由

<a id="sec-15"></a>

## 15. 不整合検査

### FR-016 不整合検査

プラグインは、外部から与えられた完全な管理対象指定に従って確定した管理対象文書一覧を走査し、少なくとも次の不整合を一覧化できること。

- 文書 ID が存在しない
- 文書 ID の重複
- 壊れた参照
- 文書 ID と物理パスの不一致
- 存在しないセクションへの参照
- ToC と実体ファイルの不一致
- 参照先として指定されたディレクトリを正常に検索した結果、文書 ID が見つからなかった参照
- 参照先ディレクトリを検索できず、存在・不在を判定できなかった参照
- 更新済みだが影響調査が完了していない文書

## 受け入れ条件案

### AC-003 参照パス不一致の検出

文書移動後、文書 ID は正しいがリンク定義のパスが古い場合、その不一致を検出できること。

### AC-004 参照パス修正情報の通知

実際のディレクトリ検索で同じ文書 ID の現在パスを確認できた場合、古いリンク定義がある参照元文書と問題箇所、古いパスおよび確認済みの現在パスをプロジェクト管理 AI へ通知できること。現在パスを確認できない場合は、指定ディレクトリ内での不在または検査不能を通知し、保存済みデータによる推測パスを確定値として返さないこと。通知時点では、doc-link が管理対象 Markdown を変更していないこと。

### AC-006 変更影響の列挙

文書の内容を変更した場合、管理対象文書のうち、その文書を正式な記法で参照している文書を列挙できること。

### AC-007 セクション単位の限定

セクション参照を採用した場合、参照対象外のセクションだけが変更されたとき、その参照元を影響対象に含めないこと。

### AC-008 管理対象から外れた文書への参照

文書がそのキーの管理対象から外れた場合、その文書 ID を参照している対象内のすべての文書を検出できること。キーから外れたことだけを理由に参照を無効とせず、参照先として指定されたディレクトリを検索して検査状態を決めること。対象範囲外の文書を、そのキーの管理対象文書として追跡しないこと。

### AC-009 影響調査結果の記録

doc-link が参照元文書の修正を不要と判断した場合、対象となった変更、参照元、判断結果および判断根拠を記録できること。修正が必要と判断した場合は、その結果をプロジェクト管理 AI へ通知し、doc-link 自身が管理対象 Markdown を修正しないこと。

### AC-028 参照先ディレクトリ検索による検証

参照先として指定されたディレクトリを正常に検索し、記載された文書 ID を持つファイルがリンク先パスに存在する場合は、参照を正しいと判定できること。同じディレクトリ内の別パスで見つかった場合はパス不一致を検出できること。検索を完了しても見つからない場合は「指定ディレクトリ内に不在」と記録し、世界全体での不存在とは扱わないこと。

参照先ディレクトリを検索できない場合は検査不能とし、保存済みの ToC やデータベースの情報だけで参照を正しいと判定しないこと。参照先の管理キーへの所属有無によって判定を変えず、検査結果は検索後に保存すること。
