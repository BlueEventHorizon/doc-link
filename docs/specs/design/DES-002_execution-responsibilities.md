## 3. Skill と script の接続規則 DLID-gjwba2n3mq4v

doc-link の各 Skill は、呼び出し元（[プロジェクト管理 AI]）のコンテキストでそのまま実行する継承型とする。SKILL とカスタム Agent の構成は[DES-010][des-010]に定める。Skill の実行と、通知を受けた本文・リンクの修正は同じ AI が行う。script は[DLID]の書き込みと管理状態の更新だけを担い、[情報生成 AI]だけを別のコンテキストに分ける（2 番目の規則）。

1. Skill は要件で定めた順序で操作を起動するが、「前段成功」という自己申告だけで次段に進めない。script は入力に含まれる版と状態を検査し、許可されない遷移を拒否する。
2. [情報生成 AI]の入力コンテキストは生成対象の文書内容と記述上限 `L` に必要な情報だけで構成する。内部許容上限 `H`、係数、余白の存在は、プロンプト、再試行メッセージ、[情報生成 AI]が参照するルールへ渡さない。`H` を含む設計・検証情報を既に読んだ同一コンテキストを、そのまま[情報生成 AI]として使用しない。検証器の情報境界は script が担う。
3. [変更影響候補の通知]では、script が変更文書と把握済み参照元を機械的に列挙し、Skill が呼び出し元へ返す。doc-link 内で修正要否の判断、理由の生成、修正案の作成を行わない。
4. [プロジェクト管理 AI]が修正した後の再検査は新しい操作として起動する。doc-link が[Index 対象文書]の本文・参照リンクを直接修正する経路を設けない。
5. 検査・検索・[DLID]の解決・構築・[変更影響候補の通知]は異なる script 操作とする。SKILL への割り当ては DES-010 に従う。検査の SKILL は管理状態を書き換えない。`check-impact` も書き換えない（要件 [D-038][req-005-fr-015]、[DES-007 §3][des-007-sec-3]）。「不整合を通知する検査」と「ID を付与する操作」を同じ SKILL にしない。

## 4. 保留と後続設計 DLID-8ck587eq1qnd

DLID 付与操作が ID を一部の文書へ保存した後に失敗した場合、既発行 ID は不変として再実行時に再利用する必要がある（要件 [D-004][req-002-fr-001]）。検証を通って書き込んだ[DLID]は正しい値なのでロールバックせず、発行済みとして報告する。操作は正常終了させず、書き込めなかった文書ごとにパス・問題箇所・原因を報告する（要件 [FR-002][req-002-fr-002]、[NFR-005][req-001-nfr-005]）。再実行すると残りの文書を処理する。script の分割、CLI の引数形式は後続設計で扱う。Python の script は `uv run` で実行し、Python 本体と外部依存（markdown-it-py）は uv が用意する。利用者の環境の前提は uv だけとする。

doc-link が作るファイルは、すべてプロジェクトの中に置き、プロジェクトの外（OS の一時ディレクトリなど）には作らない。一時ファイル（書き込み用の一時ファイル、カスタム Agent との受け渡しファイル、検索に渡す[ToC]の写し、構築の完了結果の明細ファイル）は、[実装ガイドライン][implementation-guidelines]に従い `.temp/doc-link/<skill>/` に置く。

doc-link の管理状態は、プロジェクトルート直下の `.doc-link/` に JSON ファイルとして保存し、git で追跡する。並行するブランチで更新しても衝突が差分として読めるよう、次の 2 種類のファイルに分ける。

- [文書情報]：[文書 ID]ごとに 1 ファイルとする。二つのブランチで衝突するのは、両方で同じ文書を変えた場合に限られる。
- [確定 ToC]：[ToC 識別キー]ごとに 1 ファイルとする。

script は同じ内容から常に同じバイト列を出力する（UTF-8、オブジェクトのキーの並べ替え、インデントの固定）。内容が変わらないファイルは書き換えない。[文書情報]と[ToC]のファイルが衝突した場合は、どちらかの内容を採って構築を再実行すれば、[内容ハッシュ]が変わった文書だけの AI 生成で収束する。書き込みの単位は[DES-005 §5][des-005-sec-5]に定める。
