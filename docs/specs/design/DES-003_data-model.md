# DES-003 論理データモデル

**状態**: 承認済み\
**更新日**: 2026-10-28\
**根拠**: [ToC の情報要件][req-003-sec-7]、[設計書の構成][readme]

<a id="sec-1"></a>

## 1. モデルの境界

このモデルは情報の同一性、関係、版、一次情報源を定義し、物理スキーマを指定しない（保存方式は JSON ファイル、[DES-002 §4][des-002-sec-4]）。「現在の現物」「最後に確定した索引」「変更影響候補の報告まで処理済みの比較基準」は別の情報である。キー所属は参照先の有効性を制限しない。

<a id="sec-2"></a>

文書情報は `doc_link_id` ごとに一つのファイルとして一か所に保存し、キー別に複写しない（決定: 旧 R-001）。複数キーから同じ文書情報を参照するため、一つの検索結果で異なる版のフィールドが混在することはない。ToC の確定版が表すのはキー別の索引状態（所属、参照関係、反映済みハッシュ、検査結果）であり、文書情報を含まない。文書情報は文書単位で確定し、ToC が古い版のキーからも最新が見える（決定: 旧 R-004、要件 D-024）。

<a id="sec-3"></a>

## 3. 多重度と範囲

- 一つの管理キーは、指定された時点の対象集合として複数の文書 ID を持つ。一つの文書 ID は複数キーに所属できる。所属はキーごとの対象走査によって確定する。
- 一つの文書は複数の参照記述を持てる。参照先 ID は管理対象外でもよく、参照先が索引にないことと、指定ディレクトリ内に実体がないことは別である。
- 逆参照は、走査して登録した参照元から得られる派生情報である。世界中のすべての参照元の一覧ではない。
- 一つのキーには現在公開する ToC の確定版が高々一つある。初回構築前はゼロである。候補版は公開版ではない。
- セクションは、見出しの直前に置いたセクションの DLID で識別する。ID 付与操作はすべての見出しに DLID を付ける。ID 付与操作の後に追加され、まだ DLID を持たないセクションは安定した識別を持たず、見出し文字列を恒久 ID として扱わない（要件 D-033）。

<a id="sec-4"></a>

## 4. 値の意味と鮮度

文書 ID と内容ハッシュは異なる。ID は発行時に固定され、内容ハッシュは観測した原文に応じて変わる。リンク先パスの修正も内容ハッシュを変える（要件 D-039）。パスの不一致は参照記述と実走査で検出する。

参照検査結果の「一致」は、記録されたディレクトリと検査時点についてのみ成立する。検索時点での現在の正しさを主張するには再走査が必要である。対象文書の鮮度と参照先の鮮度は独立した属性として扱う。

管理対象から離脱した文書は、指定キーの確定版から除く。対象範囲の外へ実体を探しに行かず、削除と範囲外への移動を区別しない。ただし、残存する参照記述の検査は、その記載パスが指定するディレクトリの走査結果で決める。

<a id="sec-5"></a>

## 5. 未決の関係

現時点で未決の関係はない。文書 ID の発行方式と一意性は要件 D-028／D-030 で決定した（要件 U-016）。
