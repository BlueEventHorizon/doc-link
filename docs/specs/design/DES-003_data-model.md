# DES-003 論理データモデル DLID-r0cbjnptm8qv

<a id="sec-1"></a>

## 1. モデルの境界 DLID-3wwk8rkdkpam

このモデルは情報の同一性、関係、版、一次情報源を定義し、物理スキーマを指定しない（保存方式は JSON ファイル、[DES-002 §4][des-002-sec-4]）。「現在の現物」と「最後に確定した索引」は別の情報である。通知の状態は持たない（要件 [D-038][req-005-fr-015]）。キー所属は参照先の有効性を制限しない。

[文書情報]は `doc_link_id` ごとに一つのファイルとして一か所に保存し、キー別に複写しない（要件 [D-024][req-003-fr-004]）。複数キーから同じ[文書情報]を参照するため、一つの検索結果で異なる版のフィールドが混在することはない。[確定 ToC]が表すのは[ToC]（所属、参照関係、[反映済みハッシュ]、検査結果）であり、[文書情報]を含まない。[文書情報]は文書単位で確定し、[ToC]が古い版のキーからも最新が見える（要件 [D-024][req-003-fr-004]）。

## 3. 多重度と範囲 DLID-1dsp2vtrmj3q

- 一つの[ToC 識別キー]は、その時点の[Index 済みリスト]として複数の[文書 ID]を持つ。一つの[文書 ID]は複数キーに所属できる。所属はキーごとの対象走査によって確定する。
- 一つの文書は複数の参照記述を持てる。参照先 ID は Index 対象外でもよく、参照先が索引にないことと、指定ディレクトリ内に実体がないことは別である。
- 逆参照は、走査して登録した参照元から得られる派生情報である。世界中のすべての参照元の一覧ではない。
- 一つのキーには現在公開する[確定 ToC]が高々一つある。初回構築前はゼロである。[ToC 候補]は[確定 ToC]ではない。
- セクションは、見出しの行の末尾に置いた[セクション ID]で識別する。DLID 付与操作はすべての見出しに[DLID]を付ける。DLID 付与操作の後に追加され、まだ[DLID]を持たないセクションは安定した識別を持たず、見出し文字列を恒久 ID として扱わない（要件 [D-033][req-005-sec-13-1]）。

<a id="sec-4"></a>

## 4. 値の意味と鮮度 DLID-61vvsqe67hht

[文書 ID]と[内容ハッシュ]は異なる。ID は発行時に固定され、[内容ハッシュ]は観測した原文に応じて変わる。リファレンスリンクの定義の行は[内容ハッシュ]に含めない（要件 [D-039][req-003-sec-10-1-2]）。リンク先パスの修正とパスの不一致は、参照記述と実走査で検出する。

参照検査結果の「一致」は、記録されたディレクトリと検査時点についてのみ成立する。検索時点での現在の正しさを主張するには再走査が必要である。対象文書の鮮度と参照先の鮮度は独立した属性として扱う。

Index 対象から離脱した文書は、指定キーの[確定 ToC]から除く。対象範囲の外へ実体を探しに行かず、削除と範囲外への移動を区別しない。ただし、残存する参照記述の検査は、その記載パスが指定するディレクトリの走査結果で決める。
