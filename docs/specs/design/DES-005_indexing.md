# DES-005 対象確定・ID 付与・ToC 構築設計

**状態**: 承認済み\
**更新日**: 2026-10-30\
**根拠**: [管理対象と ID][req-002]、[ToC 管理][req-003]

<a id="sec-1"></a>

## 1. 入出力と実行境界

入力は管理キー、当該キーの完全な管理対象指定、対象 Markdown、当該キーの最後の確定版、処理済み比較基準である。出力は、新しい確定版または失敗診断、未処理変更、参照検査結果である。処理の段階は [DES-004 の B-01〜B-09][des-004] に従い、途中候補を現在版として公開しない。初回は既存版がなくても、ID 確認の後に候補を作り確定する。構築は管理対象 Markdown を書き換えない（要件 D-035）。

<a id="sec-2"></a>

## 2. 対象確定・ID 確認と ID 付与

1. `--key` と完全な desired state、または予約キー `all` の単体モードを検証する。Forge の設定ファイルは読まず、呼び出し元が解決した指定を使う。引数の組み合わせは DocAdvisor の `index-docs` と同じとし、次に反する指定は拒否して報告する（要件 [REQ-002 §6.1][req-002-sec-6-1]）。
   - `--paths` と `--paths-json`、`--dirs` と `--dirs-json`、`--exclude` と `--exclude-json` は、それぞれ併用でき、連結する。
   - 対象指定（`--paths` 系、`--paths-file`、`--dirs` 系、`--exclude` 系）には `--key` が必要である。`--key` を省くと単体モードになり、対象指定を併せて渡すことはできない。`--key all` は予約語なので指定できない。
   - `--all` は対象指定と併用できない。引数が無いときは `--all` として扱う。
   - `--paths-file` はほかの対象指定と併用できない。
   - `--exclude` 系は `--all`・`--paths-file` と併用できない。
2. ディレクトリ・パターンを具体的な Markdown 一覧に展開し、除外を適用する。指定外の実体は対象へ加えない。正規化した指定は次回の検索で再展開できる形に保つ。
3. 全対象の frontmatter を読み、認識できる `doc_link_id` を取得する。ID のない文書と、同じ ID を持つ複数の文書は ID 確定済み一覧から除き、パスとともに報告して ID 付与操作での解消を案内する。これらを理由に後続へ進むことを止めない（要件 D-036）。読み取りに失敗した文書があれば障害として後続へ進まない。

<a id="sec-2-1"></a>

### 2.1 ID 付与操作

ID 付与操作は構築とは別に、ユーザーまたはプロジェクト管理 AI が明示的に起動する（要件 D-035）。起動を書き込みの承認とし、書き込み前に改めて承認を求めない。書き込んだ文書・位置・DLID と、書き込めなかった文書を結果として返す（要件 D-040）。対象は §2 の 1・2 と同じ引数と規則で確定する（要件 D-041）。管理キーは対象の指定にだけ使い、ID 付与操作はキーごとの状態を持たない。指定の検証と展開は §2 の対象確定と同じ script を使う。

1. 対象文書の `doc_link_id` とセクションのアンカー行の DLID を読み、管理状態に記録された全キーの DLID と今回走査した DLID に照合する。
2. 同じ DLID が複数の箇所（セクションの DLID は同じ文書の中を含む）にあれば、管理状態に記録されたその DLID のパスと一致するものを原本の候補として利用者へ示す。利用者が原本を確定した後、原本以外へ新しい DLID を発行する。文書 ID を再発行する複製では、その文書のセクションの DLID もあわせて再発行する。候補を一つに絞れなければ利用者に原本を指定させる（決定: U-017、要件 D-029）。
3. 認識できる `doc_link_id` がない文書に新しい値を発行・保存する。利用者や生成 AI に採番させない。
4. セクションの DLID を持たないすべての見出しにセクションの DLID を発行し、アンカー行を書き込む（要件 D-033）。`doc_link_id` を持つ Markdown を指し title に DLID の無いリンクに、参照先の DLID を加える。初回の移行に限らず、ID 付与操作が起動されるたびに指定された対象文書について行い、参照先を一つに特定できないリンクには加えず報告する（要件 D-034、D-042）。書き込むのは指定された対象文書だけである。参照先の見出しが対象外の文書にあり、セクションの DLID が無い場合は、その文書へ書き込まず、リンクにも DLID を加えず、参照先の文書を対象に含めて再実行するよう報告する。

DLID の書き込みだけが管理対象 Markdown への書き込みである（要件 D-031）。途中で失敗した場合に既に保存された ID は「発行済み」として報告し、次回に内容から再計算しない。発行仕様は 60 ビット乱数の Crockford Base32 12 文字とし、一意性は確率的な一意性とする（決定: U-001／U-016、要件 D-028、D-030）。重複の照合の範囲は、管理状態に記録された全キーの DLID と今回走査した DLID とする。書き込み済みの DLID はロールバックしない。

<a id="sec-3"></a>

## 3. 変更集合の確定

ID 確定済み一覧を現在のキーの ToC と照合し、少なくとも「新規」「対象離脱」「同じ ID のパス変更」「内容ハッシュの変更」「参照記述・物理パスの変更」を独立に記録する。一件が複数種別に該当してよい。対象離脱は今回の対象一覧にないことだけで判定し、範囲外を探索して削除か移動かを決めない。

ToC の反映済みハッシュと現物を比較して**索引更新対象**を決め、別の処理済み比較基準と現物を比較して**未報告の変更**を決める。この段階では AI 要約、参照先の実走査、ToC 書き込みを行わない。現在ハッシュが既に ToC に反映済みでも比較基準が旧値なら、要約を再生成せず未報告の変更を残す。

<a id="sec-4"></a>

## 4. 必要情報の取得と候補確定

変更種別から更新計画を作り、変更のない文書の AI 生成情報は再利用する。パスだけの変更は現在パスを更新し、内容が同じなら要約を作り直さない。「指定キーの ToC では新規」と「文書 ID 自体が新規」は区別する。文書 ID と内容ハッシュに対応する検証済み文書情報が既にある場合、キーへの追加だけを理由に AI へ再生成させない。再利用できる情報がない新規文書、または内容ハッシュが変わった文書に必要な情報だけ AI に生成させ、script が必須値と長さを検査する。指定されていないキーの ToC を更新せず、そのキーの ToC を構築結果の正しさの根拠にも使わない。参照記述は現物から抽出し、参照先の実走査結果と逆参照を候補に組み立てる。文書情報はキーから独立して文書ごとに一つ保存し、各キーは同じ最新のものを参照する（決定: 旧 R-001）。

候補は少なくとも ID の一意性、対象集合との対応、参照と逆参照の対応、必須フィールドを検査する。構築中に現物が変わった場合の再評価はしない。その変更は次の `check-toc` が検出する。検査済み候補（そのキーの所属、参照関係、反映済みハッシュ、検査結果）だけを一括して公開し、失敗時は旧確定版と旧比較基準を保持する。文書情報はこの一括公開に含めず、文書ごとに確定する（要件 D-024）。

<a id="sec-5"></a>

## 5. 書き込みの単位

文書情報の書き込みと、キー別の索引状態の一括公開は、それぞれ一時ファイルに書いてから置き換える（`os.replace`）ことで、書き込み途中の内容を公開しない。文書情報は文書ごとに 1 ファイル、キー別の索引状態はキーごとに 1 ファイルを置き換える（[DES-002 §4][des-002-sec-4]）。同じ作業ツリーで複数の構築や ID 付与操作を同時に実行することは想定せず、ロックを設けない。同時に実行した場合に起きるのは、要約の二重生成や、後から確定した版による上書きであり、再実行で収束する。検索は確定済みのファイルを読む。

構築が途中で失敗しても、それまでに確定した文書情報は戻さない。文書情報は文書の現在の事実であり、キー別の索引状態ではないためである。

参照先の指定ディレクトリ内不在とパス不一致は、候補に記録する検査結果であって確定失敗ではない（決定: U-020、要件 D-025）。

<a id="sec-6"></a>

## 6. 完了と再実行

ToC 確定だけでは処理済み比較基準を進めない。比較基準は、`check-impact` が報告を返すときに進める（[DES-007 §3][des-007-sec-3]、要件 D-038）。失敗時は段階、対象 ID・パス、原因、公開版の有無、未報告の変更を返す。再実行時は確定版・比較基準・現物から再判定し、旧版に取り込まれた要約を不必要に繰り返さない。
