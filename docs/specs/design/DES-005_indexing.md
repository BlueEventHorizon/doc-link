# DES-005 対象確定・DLID 付与・[ToC]構築設計 DLID-yhb7552z92k6

<a id="sec-1"></a>

## 1. 入出力と実行境界 DLID-racs51864j70

入力は[ToC 識別キー]、当該キーの完全な[Index 対象指定]、対象 Markdown、当該キーの最後の[確定 ToC]である。出力は、新しい[確定 ToC]または失敗診断、変更集合、参照検査結果である。完了結果は、判断に要る項目と件数だけを標準出力へ返し、変更集合などの全件は明細のファイルへ書く（§4、要件 [D-059][req-003-sec-11-2-4]）。処理の段階は[DES-004 の B-01〜B-09][des-004]に従い、途中候補を現在版として公開しない。初回は既存版がなくても、ID 確認の後に候補を作り確定する。構築は[Index 対象文書]を書き換えない（要件 [D-035][req-002-fr-001]）。

## 2. 対象確定・ID 確認と DLID 付与 DLID-6b3d2nqzpw75

1. `--key` と完全な desired state、または予約キー `all` の単体モードを検証する。Forge の設定ファイルは読まず、呼び出し元が解決した指定を使う。引数の組み合わせは次のとおりとし、これに反する指定は拒否して報告する（要件[REQ-002 §6.1][req-002-sec-6-1]）。
   - `--paths` と `--paths-json`、`--dirs` と `--dirs-json`、`--exclude` と `--exclude-json` は、それぞれ併用でき、連結する。
   - 対象指定（`--paths` 系、`--paths-file`、`--dirs` 系、`--exclude` 系）には `--key` が必要である。`--key` を省くと単体モードになり、対象指定を併せて渡すことはできない。`--key all` は予約語なので指定できない。
   - `--all` は対象指定と併用できない。引数が無いときは `--all` として扱う。
   - `--key` を指定して対象指定を渡さない場合は拒否する。対象の無い[ToC]は、処理を正常完了として扱えない状態だからである（要件[REQ-001 §17.1][req-001-sec-17-1]）。
   - `--paths-file` はほかの対象指定と併用できない。
   - `--exclude` 系は `--all`・`--paths-file` と併用できない。
2. ディレクトリ・パターンを具体的な Markdown 一覧に展開し、除外を適用する。指定外の実体は対象へ加えない。正規化した指定は次回の検索で再展開できる形に保つ。展開と除外の照合は次のとおりとする。
   - `--dirs` 系の要素に `*`・`?`・`[` があればパターンとして展開する。一致したディレクトリは配下の Markdown を再帰的に集め、一致した Markdown ファイルはそのまま加える。無ければ、そのディレクトリ配下の Markdown を再帰的に集める。`/` を含むパターンの要素 `**` は、0 階層以上のディレクトリに一致する（`docs/**/design/` は `docs/design` と `docs/a/b/design` の両方に一致する。要件 [D-052][req-002-sec-6-1-2]）。
   - `--exclude` 系の要素は、`/` を含まなければ、どの階層の同じ名前のディレクトリとも完全一致で照合し、ファイル名とは照合しない。`/` を含めば、パスとの完全一致、またはその配下で照合する。`*`・`?`・`[` を含む要素はパターンとし、`--dirs` 系のパターンと同じ規則で照合する。`/` を含まなければどの階層の名前（ディレクトリ名・ファイル名）と、含めばパスまたはその祖先のパスと照合し、一致したものとその配下を除く。パターンを照合するのは、要件がパターンでの除外を求めるためである（[REQ-002 §6.1][req-002-sec-6-1]）。
   - `--all` の走査と `--dirs` 系の展開では、[REQ-002 §6.1][req-002-sec-6-1]の固定の除外に挙げた名前のディレクトリの配下を対象にしない。ファイルを直接指定したもの（`--paths` 系、`--paths-file`）には適用しない。指定したディレクトリそのものが、この名前（またはその配下）のときは、対象を 0 件にするだけでなく、`problems` に報告する（要件 [D-054][req-002-fr-002]）。`.temp` を除くのは、doc-link の一時ファイルの置き場であり（[DES-002 §4][des-002-sec-4]）、そこに書く Markdown を索引しないためである。
   - パスの正規化、Markdown の判定、シンボリックリンクと存在しないパスの扱いは次のとおりとする。
     - パスは NFC に揃え、`./` と、プロジェクトルートの中に収まる `..` を解決する。ルートの外に出るパスは拒否する。
     - すべての指定方法（`--paths` 系、ディレクトリの走査、パターンに直接一致したファイル）で、拡張子 `.md` を大文字小文字を区別せずに Markdown とする。`.markdown` は Markdown としない。
     - シンボリックリンクはたどり、同じ実体を二度数えない。リンクの実体がどこにあっても、たどったプロジェクト内のパスで扱う。実体がプロジェクトの外にあるリンクも、対象にするかを利用者に確認しない。確認の結果で一覧が変わると、保存した指定から構築時と同じ一覧を得られないためである（要件 [D-020][req-003-sec-7-5]）。プロジェクトの外の実体は、読み、[DLID]の付与では実体へ書き込む。書き込む範囲は[DLID]だけで変わらない（要件 [D-049][req-002-sec-6-1-4]）。
     - 存在しないパスと Markdown でないパスは、対象から除いて報告し、残りの処理を続ける。
     - 大文字小文字だけが異なるパスがあるとき、`--all` で対象が 100 件を超えるときは警告する。
3. 全対象の frontmatter を読み、認識できる `doc_link_id` を取得する。
   - ID が無い文書と ID が重複する文書は、[確定 Index 対象リスト]に入れない。
   - 入れなかった文書は、パスを報告する。
   - 構築は続ける（要件 [D-036][req-002-sec-9-1]）。
   - 文書を読めなかったときは、構築を止める。

### 2.1 DLID 付与操作 DLID-kxx8fczbwref

DLID 付与操作は構築とは別に、ユーザーまたは[プロジェクト管理 AI]が明示的に起動する（要件 [D-035][req-002-fr-001]）。起動を書き込みの承認とし、書き込み前に改めて承認を求めない。書き込んだ件数（文書の ID・セクションの ID・置き換えた[DLID]の件数）と、書き込めなかった文書を結果として返す。書き込んだ文書・位置・[DLID]の明細は返さない（要件 [D-040][req-002-sec-9-2]）。書き込めなかった文書が 1 件でもあれば操作を失敗とし、その文書ごとにパス・問題箇所・原因を返す（要件 [FR-002][req-002-fr-002]、[NFR-005][req-001-nfr-005]）。対象は §2 の 1・2 と同じ引数と規則で確定する（要件 [D-041][req-002-sec-9-2]）。[ToC 識別キー]は対象の指定にだけ使い、DLID 付与操作はキーごとの状態を持たない。指定の検証と展開は §2 の対象確定と同じ script を使う。

1. 対象文書の `doc_link_id` と、見出しの行の末尾の[セクション ID]を読み、今回走査した[DLID]どうしを照合する。管理状態は、重複した[DLID]の原本の候補（記録されたパス）を得るために読む。
2. 同じ[DLID]が複数の箇所（[セクション ID]は同じ文書の中を含む）にあれば、管理状態に記録されたその[DLID]のパスと一致するものを原本の候補として利用者へ示す。利用者が原本を確定した後、原本以外へ新しい[DLID]を発行する。[文書 ID]を再発行する複製では、その文書の[セクション ID]もあわせて再発行する。候補を一つに絞れなければ利用者に原本を指定させる（要件 [D-029][req-002-fr-002]）。
3. 認識できる `doc_link_id` がない文書に新しい値を発行・保存する。利用者や[情報生成 AI]に採番させない。
4. [セクション ID]を持たないすべての見出しに[セクション ID]を発行し、見出しの行の末尾に書き込む（要件 [D-033][req-005-sec-13-1]）。初回の移行に限らず、DLID 付与操作が起動されるたびに指定された対象文書について行う。書き込むのは指定された対象文書だけである。リンクとその title は書き換えない（要件 [D-034][req-002-sec-9-2]、[D-042][req-005-fr-016]）。

[DLID]の書き込みだけが[Index 対象文書]への書き込みである（要件 [D-031][req-001-nfr-004]）。途中で失敗した場合に既に保存された ID は「発行済み」の件数として報告し、次回に内容から再計算しない。発行仕様は 60 ビット乱数の Crockford Base32 12 文字とし、一意性は確率的な一意性とする（要件 [D-028][req-002-fr-001]、[D-030][req-002-fr-002]）。重複の照合の範囲は、今回走査した[DLID]とする。走査した範囲に 1 つしかない[DLID]は、移動か複製かによらず正しいとみなし、重複としない（要件 [D-050][req-002-fr-002]）。検証を通って書き込んだ[DLID]はロールバックしない。検証で[DLID]以外の差分が見つかった文書は、その文書への書き込みを取り消す（要件 [D-031][req-001-nfr-004]）。

## 3. 変更集合の確定 DLID-ext9ze054hbx

[確定 Index 対象リスト]を現在のキーの[ToC]と照合し、少なくとも「新規」「対象離脱」「同じ ID のパス変更」「[内容ハッシュ]の変更」「参照記述・物理パスの変更」を独立に記録する。参照記述は、title に記録した[内容ハッシュ]を除いて比べる（要件 [REQ-003 §10.2][req-003-sec-10-2]）。一件が複数種別に該当してよい。対象離脱は今回の[Index 対象リスト]にないことだけで判定し、範囲外を探索して削除か移動かを決めない。

セクション単位の変更検出（要件 [FR-012][req-003-fr-012]）は、[確定 ToC]のセクションエントリと現物のセクションを[セクション ID]で突き合わせて行う。区別は次のとおりとし、一つのセクションが複数に該当してよい。

- 現物にだけある[セクション ID]は、追加とする。
- [確定 ToC]にだけある[セクション ID]は、削除とする。
- 同じ[セクション ID]で、所属する[文書 ID]または文書内の位置が違うものは、移動とする。
- 同じ[セクション ID]で、見出しが違うものは、見出し変更とする。
- 同じ[セクション ID]で、見出しが同じで、セクションの[内容ハッシュ]が違うものは、本文変更とする。見出しも違うときは、本文の変更の有無を区別しない（セクションの範囲に見出しを含むため。[DES-008 §2][des-008-sec-2]）。

[ToC]の[反映済みハッシュ]と現物を比較して**索引更新対象**を決める。この段階では AI 要約、参照先の実走査、[ToC]書き込みを行わない。

移動（同じ ID のパス変更）だけは、比べる相手が構築の途中で書き換わる。[ToC]は[文書 ID]と[反映済みハッシュ]を持ち、パスは持たない。パスは全キーで共有する[文書情報]が持ち、構築の最初の比較の後に、script が新しくする（パスだけの変更は直ちに、本文も変わった文書は生成結果の保存で）。そのため、あとの比較には移動が現れない。そこで script が、移動を検出するたびに（構築の `advance` ごとに、パスを新しくする前に）、[文書 ID]・前のパス・後のパスを、[ToC 識別キー]ごとの記録ファイル（`.temp/doc-link/index-docs/`）へ足す。同じ組は足さない。完了結果は、最後の比較に、記録した移動を合わせて作る。文書ごとに、記録の最初の前のパスと現在のパスを比べ、違えば移動、同じなら（移動して元に戻した場合）移動なしとする。同じ文書かは[文書 ID]で判定する。記録は、[確定 ToC]を公開した後に削除し、構築が失敗したときは残す（構築のやり直しで使う）。複数のキーで同じ文書を使うとき、移動を報告するのは、[文書情報]のパスを新しくした構築であり、あとに構築するキーには現れない。記録の読み書きと集計は script が行い、AI は行わない。本文変更・参照変更・セクションの変更は、[ToC]と比べるので、この記録を要しない。

## 4. 必要情報の取得と候補確定 DLID-dfsegbf7p2q9

変更種別から更新計画を作り、変更のない文書の AI 生成情報は再利用する。パスだけの変更は現在パスを更新し、内容が同じなら要約を作り直さない。「指定キーの[ToC]では新規」と「[文書 ID]自体が新規」は区別する。[文書 ID]と[内容ハッシュ]に対応する検証済み[文書情報]が既にある場合、キーへの追加だけを理由に AI へ再生成させない。再利用できる情報がない新規文書、または[内容ハッシュ]が変わった文書に必要な情報だけ AI に生成させ、script が必須値と長さを検査する。指定されていないキーの[ToC]を更新せず、そのキーの[ToC]を構築結果の正しさの根拠にも使わない。参照記述は現物から抽出し、参照先の実走査結果と逆参照を候補に組み立てる。[文書情報]はキーから独立して文書ごとに一つ保存し、各キーは同じ最新のものを参照する（要件 [D-024][req-003-fr-004]）。

候補は少なくとも ID の一意性、[確定 Index 対象リスト]との対応、参照と逆参照の対応、必須フィールドを検査する。構築中に現物が変わった場合の再評価はしない。その変更は次の `check-toc` が検出する。検査済み候補（そのキーの所属、参照関係、[反映済みハッシュ]、検査結果）だけを一括して公開し、失敗時は旧[確定 ToC]を保持する。[文書情報]はこの一括公開に含めず、文書ごとに確定する（要件 [D-024][req-003-fr-004]）。

完了結果は、判断に要る項目と件数だけを標準出力へ返し、全件の明細は作業ファイルへ書く（要件 [D-059][req-003-sec-11-2-4]）。標準出力は、次を持つ。

- 確定結果（版、[確定 ToC]を書き換えたか）
- 変更の種別ごとの件数。文書は、新規・本文変更・参照変更・移動・改名・離脱・変更なしに分け、セクションは、追加・削除・移動・見出し変更・本文変更に分ける。複数の種別に該当する文書・セクションは、それぞれの種別に数える。該当が無い種別も、0 として必ず持つ。確定した文書の件数と、初回構築かも持つ
- 生成した文書の件数
- 参照検査結果（分類ごとの件数と、一致以外の検出事項）
- ID 未付与・重複で除外した文書
- 報告すべき問題と警告
- 明細ファイルの絶対パス

明細ファイルは、変更集合（§3 の記録。文書・セクションごとの変更前後の値を含む）と、生成した文書の一覧を、全件持つ。[ToC 識別キー]ごとに 1 つを `.temp/doc-link/index-docs/` に置く。script が一時ファイルへ書き終えてから 1 回の置き換えで公開し（組み立て途中のものを読ませない）、同じ[ToC 識別キー]の次の構築で置き換える。[確定 ToC]を公開する前に書き、書けないときは公開せずに構築の失敗として報告する。構築が失敗したときは、パスを返さない。

## 5. 書き込みの単位 DLID-hs82xgzwkpyz

[文書情報]の書き込みと、[ToC]の一括公開は、それぞれ一時ファイルに書いてから置き換える（`os.replace`）ことで、書き込み途中の内容を公開しない。[文書情報]は文書ごとに 1 ファイル、[ToC]はキーごとに 1 ファイルを置き換える（[DES-002 §4][des-002-sec-4]）。同じ作業ツリーで複数の構築や DLID 付与操作を同時に実行することは想定せず、ロックを設けない。同時に実行した場合に起きるのは、要約の二重生成や、後から確定した版による上書きであり、再実行で収束する。検索は確定済みのファイルを読む。

構築が途中で失敗しても、それまでに確定した[文書情報]は戻さない。[文書情報]は文書の現在の事実であり、[ToC]ではないためである。

参照先の指定ディレクトリ内不在とパス不一致は、候補に記録する検査結果であって確定失敗ではない（要件 [D-025][req-005-fr-009]）。
