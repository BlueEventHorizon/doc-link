# DES-006 文書検索設計

**状態**: 承認済み\
**更新日**: 2026-10-31\
**根拠**: [文書検索要件][req-004]、[DLID の解決の要件][req-002-sec-9]

<a id="sec-1"></a>

## 1. 検索前の判定

検索要求はキー（省略時は予約キー `all`）とタスク・検索条件を持つ。指定キーの確定済み ToC がなければ、検索せず初回構築が必要と返す。確定版があれば、その版に保存した再解釈可能な対象指定で現在の一覧を走査し、ID、パス、比較値を版と照合する。新しい完全な対象指定が同時に与えられた場合はそれを優先する。対象指定の展開・現物の読取りが失敗した場合は「更新不要」と判定しない。

検索前検査の結果は「再構築不要」「再構築必要」「判定不能」を区別する。比較で再構築不要なら確定版を検索する。再構築が必要なら Skill がユーザーへ「再構築後に検索」「既存版のまま検索」の二択を確認する。確認時には script が照合結果から数えた再構築の規模（新規・離脱・パス変更・内容変更・ID 未付与・ID 重複の件数と、同じ内容ハッシュの文書情報がなく AI 生成が必要な件数）を示す（要件 D-027）。参照先の走査結果と生成にかかる時間はこの時点では分からないため示さない。前者は [DES-005][des-005] が正常確定した場合だけ新版を検索し、失敗時に旧版で黙って検索しない。後者は ToC と比較基準に書き込まず、結果に古い版であることを明示する。古い版から使うのはキー別の索引状態（所属、参照関係、反映済みハッシュ、検査結果）であり、文書情報は最新のものを表示する（要件 D-024）。検索は確定済みのファイルを読む。

対象指定の展開または現物の読取りに失敗した「判定不能」は、再構築不要・再構築必要のどちらにも読み替えない。判定不能は障害として扱い、検索を停止して、判定できなかった対象と原因を返す。旧版での検索を利用者に提示しない（要件 D-026）。frontmatter の解析不能（ID 欠落扱い）や対象ディレクトリの消失（対象離脱）は判定不能ではない。前者は ID 未付与として件数を示し（要件 D-036）、後者は再構築必要に分類する。

<a id="sec-2"></a>

## 2. 検索結果の契約

各候補は文書 ID、確定版に記録されたパス、関連理由、必要ならセクション、使用した管理キー・ToC 版・鮮度判定を持つ。「既存版のまま」を選んだ場合は、その版が現在の対象集合を反映していない可能性を結果全体にも付ける。文書が現物で移動・削除されていても、古い索引のパスを現在の実体パスとして断定しない。

script は確定版と入力キーに基づき、検索に使う ToC と版・鮮度を固定して渡す。関連度の判定の方式は DocAdvisor と同じであり、文書をパスではなく DLID で識別する点と、§1 の検索前検査と本節の結果の契約が異なる。自然言語タスクとの意味的な関連度は、読み取り専用の検索 worker（カスタム Agent）が ToC 全体を読んで判定し、関連する文書と理由を返す。取りこぼしを避けるため、意味的に近い文書を広く拾う。worker は存在しない ID を補わず、索引の版・パスを訂正せず、ToC と管理状態を変更しない。

<a id="sec-3"></a>

## 3. DLID の解決

`resolve-dlid` は DLID の並びを受け取り、DLID ごとに解決結果を返す（要件 FR-018、D-047）。管理キーは受け取らない。解決は確定済みの管理状態の記録と、記録されたパスの現物だけで行う。

1. 文書の DLID は、その文書情報に記録された現在パスを引く（[DES-003 §2][des-003-sec-2]）。セクションの DLID は、全キーの ToC の確定版のセクションエントリから所属する文書 ID を引き、その文書情報の現在パスを使う。セクションを別の文書へ移した後に一部のキーだけを再構築すると、所属する文書の記録がキーごとに異なる。この場合は記録された所属文書をすべて候補にする。
2. 記録されたパスのファイルを読み、文書の DLID は frontmatter の `doc_link_id` と、セクションの DLID はアンカー行の DLID と照合する（[DES-008 §1][des-008-sec-1]）。一致すれば「解決済み」としてパスを返す。セクションには見出しの文字列と、アンカー `#DLID-…` を添える。
3. ファイルが無い場合と DLID が一致しない場合は、記録されたパスを添えて「記録されたパスに無い」と返す。候補が複数あるときは、一致した候補だけを解決済みとし、どれも一致しなければ記録されたパスをすべて添える。ほかの場所を探索しない。§2 と同じく、記録されたパスを現在の実体パスとして断定しない。記録はその文書を含む ToC を再構築すると更新される。ファイルを読めない場合は、その DLID について原因を返す。
4. どの記録にも無い DLID は「記録が無い」と返す。管理状態を読み取れない場合は全体を失敗とし、原因を返す。

ToC、管理状態、管理対象 Markdown には書き込まない。
