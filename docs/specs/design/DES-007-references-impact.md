# DES-007 参照検査と変更影響候補の通知

**状態**: Draft 0.1・未承認\
**更新日**: 2026-10-26\
**根拠**: [参照と変更通知の要件][req-005]

<a id="sec-1"></a>

## 1. 正式な参照と検査根拠

正式な参照は、Markdown のリンクのうち title の最後の語が DLID であるものから抽出する（要件 D-032）。参照先は文書またはセクションの DLID である。参照元 ID、記載位置、参照先 ID、リンク定義の相対パスを別々に保持する。文書 ID が同じキーにあるか、保存済み ToC・DB にあるかは、現在の参照の正しさの判定に使わない。title に DLID の無いリンク、ファイル名、自然言語の言及は正式な参照に含めない（要件 D-032）。

script は参照元からリンク定義の相対パスを解決し、指定された**ディレクトリ**を実走査して候補文書の frontmatter ID を照合する。結果は「一致」「同ディレクトリ内の別パスに同 ID がありパス不一致」「走査完了した指定ディレクトリ内に不在」「走査不能」のいずれか。指定ディレクトリ自体が存在しない場合は「不在」とし、ディレクトリを読めない場合だけを「走査不能」とする（要件 D-025）。結果は検査ディレクトリ・時点・証拠を伴う。同一 ID が複数見つかった場合は一意の現在パスを推定せず、重複診断にする。参照先が管理キーの対象外でも、この走査を省略しない。

パス不一致の修正先は、実走査で同じ ID の実体を一意に確認した場合にだけ通知する。指定ディレクトリの外へ移動した文書は、そのディレクトリの検索では発見できない。保存済みパスや別キーの情報から「現在パス」を推測して確定値として返さない（旧 R-005）。指定ディレクトリ内不在、パス不一致、走査不能はいずれも ToC 確定を妨げない（決定: U-020、要件 D-025）。

<a id="sec-2"></a>

## 2. 逆参照と影響候補

逆参照は走査済みの参照元から作る。対象の変更前後の内容比較値と、参照元を走査したキー・対象指定・時点を結び付ける。対象内の参照元が見つからないことを、世界全体に参照元がないことと同一視しない（旧 R-006）。対象文書がキーから離脱しても、残る参照元を検査し、必要な通知が済むまで当該キーの旧処理済み比較基準を保持する。

本文に意味のある変更があれば、直接参照の候補を列挙する。セクションの DLID を参照する参照元には、そのセクションの範囲に変更があった場合に通知する（要件 D-033）。文書の DLID を参照する参照元には、文書内のどこが変わっても通知する。内容の比較値は要件 D-039 の規則で計算するので、DLID の書き込みとリンク先パスだけの修正は変更として扱わない。間接の参照元は列挙しない。参照元を直すとその参照元が次の検出で変更として現れるので、間接的な影響は 1 段ずつ検出される（要件 D-043）。未決の限定を根拠に候補を勝手に除外しない。

<a id="sec-3"></a>

## 3. 変更影響候補の通知と比較基準

参照元は確定済み ToC の参照関係から取るので、ToC が現物を反映していない場合は変更影響候補を返さず、ToC の再構築を案内する（[DES-010 §1.2][des-010-sec-1-2]）。script は、処理済み比較基準と現物の内容比較値から未報告の変更を特定し、確定済みの参照関係から把握できる参照元を列挙する。Skill は変更文書 ID・箇所・比較値、参照元文書 ID・箇所・参照記述、および検査範囲をプロジェクト管理 AI へ返す。参照元がない場合も「走査した範囲では見つからない」という事実だけを返す。

doc-link は参照元の修正要否を判断せず、根拠や修正案を生成せず、本文・リンクを編集しない。修正要否の判断と修正は通知を受けたプロジェクト管理 AI が行う。

ToC の確定だけでは処理済み比較基準を進めない。変更と把握済み参照元の報告をプロジェクト管理 AI へ正常に返した時点で、報告した対象だけ現在の内容比較値へ進め、報告できなかった対象は旧値を保つ（要件 D-038）。プロジェクト管理 AI の判断や修正の結果は、比較基準を進める条件にしない（要件 FR-015）。報告前に現物が再変更された場合は新しい現在値を取得し、古い変更の報告結果を現在のものとして扱わない。処理済み比較基準は (対象文書 ID, 参照元文書 ID) の組ごとに保持し、走査に使ったキーには依存しない（決定: 旧 R-002、要件 U-010）。参照元が新たに管理対象へ加わった場合、その組がまだ処理済みでなければ、対象の内容ハッシュが変わっていなくても報告対象にする。

<a id="sec-4"></a>

## 4. 不整合検査

不整合検査は ID 欠落・重複、壊れた参照、title に DLID の無いリンク、パス不一致、検査不能、ToC と現物の差、未処理影響を一覧化する操作として扱う。検査内容ごとに `check-dlid`、`check-links`、`check-toc`、`check-impact` の SKILL に分ける（[DES-010][des-010]）。管理状態を書き換えるのは、報告を返した時点で処理済み比較基準を進める `check-impact` だけである（§3）。ID の付与は ID 付与操作だけが行うので、検査は管理対象 Markdown を変更しない（要件 D-035）。「存在しないセクション」は、リンクの title のセクションの DLID を持つアンカー行が参照先の文書に無いことで判定する（要件 D-033）。
