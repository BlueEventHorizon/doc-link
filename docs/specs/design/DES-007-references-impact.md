# DES-007 参照検査と変更影響候補の通知

**状態**: 承認済み\
**更新日**: 2026-10-29\
**根拠**: [参照と変更通知の要件][req-005]

<a id="sec-1"></a>

## 1. 正式な参照と検査根拠

正式な参照は、Markdown のリンクのうち title の最後の語が DLID であるものから抽出する（要件 D-032）。参照先は文書またはセクションの DLID である。参照元 ID、記載位置、参照先 ID、リンク定義の相対パスを別々に保持する。文書 ID が同じキーにあるか、保存済み ToC・管理状態にあるかは、現在の参照の正しさの判定に使わない。title に DLID の無いリンク、ファイル名、自然言語の言及は正式な参照に含めない（要件 D-032）。

script は参照元からリンク定義の相対パスを解決し、指定された**ディレクトリ**を実走査する。title の DLID が文書の DLID なら候補文書の frontmatter の `doc_link_id` と、セクションの DLID なら候補文書の中のアンカー行の DLID と照合する。セクションの DLID は、それを含む文書を所属文書とし、所属文書のパスをリンク先パスと比べる。リンク先のフラグメント（`#…`）は参照先の同一性の判定に使わない。結果は「一致」「同ディレクトリ内の別パスに同 ID がありパス不一致」「指定ディレクトリ内に不在」のいずれか。指定ディレクトリ自体が存在しない場合と、ディレクトリを読めない場合も「不在」とする（要件 D-025）。「一致」の場合、フラグメントがあれば別に到達先を確かめる。フラグメントを参照先文書の明示アンカー（`<a id>`）または見出しから生成されるアンカー（[DES-008 §2][des-008-sec-2]）に解決し、解決できない場合と、title がセクションの DLID で解決した見出しがそのセクションでない場合は「フラグメント不一致」とし、その DLID のセクションへ届く現在のアンカーを添える。結果は検査ディレクトリ・時点・証拠を伴う。同一 ID が複数見つかった場合は一意の現在パスを推定せず、重複診断にする。参照先が管理キーの対象外でも、この走査を省略しない。

パス不一致の修正先は、実走査で同じ ID の実体を一意に確認した場合にだけ通知する。指定ディレクトリの外へ移動した文書は、そのディレクトリの検索では発見できない。保存済みパスや別キーの情報から「現在パス」を推測して確定値として返さない（旧 R-005）。指定ディレクトリ内不在とパス不一致は ToC 確定を妨げない（要件 D-025）。

<a id="sec-2"></a>

## 2. 逆参照と影響候補

逆参照は走査済みの参照元から作る。対象の変更前後の内容ハッシュと、参照元を走査したキー・対象指定・時点を結び付ける。対象内の参照元が見つからないことを、世界全体に参照元がないことと同一視しない（旧 R-006）。処理済み比較基準はキーに依存しないので、対象文書があるキーから離脱しても除去しない。どのキーにも所属しなくなった文書の比較基準は除去する（要件 D-046）。

内容ハッシュが変わった文書とセクションについて、直接参照の候補を列挙する。内容ハッシュは原文のハッシュなので（要件 D-039）、本文・見出し・リンクの表示文字列・リンク先・title の DLID のどれが変わっても変更になる。セクションの DLID を参照する参照元には、そのセクションの範囲に変更があった場合に通知する（要件 D-033）。文書の DLID を参照する参照元には、文書内のどこが変わっても通知する。

セクションは、セクションの DLID ごとに処理済み比較基準と比べる（要件 FR-012）。見出しはセクションの範囲に含まれるので、見出しの変更は本文の変更と同じく内容ハッシュの変更になる。

| 区別 | 判定                                               | 通知                                                                                      |
| ---- | -------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 追加 | 処理済み比較基準に無い DLID が ToC に現れた        | 新規の文書と同じく新規として報告し、報告の後に処理済み比較基準を作る（要件 REQ-003 §7.5） |
| 変更 | 同じ DLID の内容ハッシュが処理済み比較基準と異なる | そのセクションを参照する参照元へ通知する                                                  |

ToC に無くなったセクションの DLID の比較基準は、通知せずに除去する。削除・移動されたセクションを指すリンクは、`check-links` が存在しないセクションへの参照・パス不一致として検出する。所属文書だけが変わり内容ハッシュが同じセクションは、変更として通知しない。

間接の参照元は列挙しない。参照元を直すとその参照元が次の検出で変更として現れるので、間接的な影響は 1 段ずつ検出される（要件 D-043）。未決の限定を根拠に候補を勝手に除外しない。

<a id="sec-3"></a>

## 3. 変更影響候補の通知と比較基準

参照元は確定済み ToC の参照関係から取るので、ToC が現物を反映していない場合は変更影響候補を返さず、ToC の再構築を案内する（[DES-010 §1.2][des-010-sec-1-2]）。script は、処理済み比較基準と現物の内容ハッシュから未報告の変更を特定し、確定済みの参照関係から把握できる参照元を列挙する。Skill は変更文書 ID・箇所・内容ハッシュ、参照元文書 ID・箇所・参照記述、および検査範囲をプロジェクト管理 AI へ返す。参照元がない場合も「走査した範囲では見つからない」という事実だけを返し、その変更を「参照元なし」の組として記録する。後から参照元が加わった場合、その参照元との組はまだ処理済みでないので報告対象になる。

doc-link は参照元の修正要否を判断せず、根拠や修正案を生成せず、本文・リンクを編集しない。修正要否の判断と修正は通知を受けたプロジェクト管理 AI が行う。

ToC の確定だけでは処理済み比較基準を進めない（要件 D-038）。script は、報告する組の比較基準を報告する内容ハッシュへ進めてから、報告の全体を結果の JSON として返す。比較基準を進められなかった場合はエラーの JSON を返し、報告しない。比較基準は旧値のままなので、次の実行で同じ変更を報告する。プロジェクト管理 AI の判断や修正の結果は、比較基準を進める条件にしない（要件 FR-015）。処理済み比較基準は (対象の文書またはセクションの DLID, 参照元文書 ID または「参照元なし」) の組ごとに保持し、走査に使ったキーには依存しない（決定: 旧 R-002、要件 U-010）。参照元が新たに管理対象へ加わった場合、その組がまだ処理済みでなければ、対象の内容ハッシュが変わっていなくても報告対象にする。

<a id="sec-4"></a>

## 4. 不整合検査

不整合検査は ID 欠落・重複、壊れた参照、title に DLID の無いリンク、パス不一致、ToC と現物の差、未処理影響を一覧化する操作として扱う。検査内容ごとに `check-dlid`、`check-links`、`check-toc`、`check-impact` の SKILL に分ける（[DES-010][des-010]）。管理状態を書き換えるのは、報告を返すときに処理済み比較基準を進める `check-impact` だけである（§3）。ID の付与は ID 付与操作だけが行うので、検査は管理対象 Markdown を変更しない（要件 D-035）。検出事項に重要度の分類は設けない。検出事項ごとの扱い（ToC の確定を妨げるか、検出後の作業）は、要件 D-025・D-036 と [DES-010][des-010] が定める。「存在しないセクション」は、リンク先パスの文書は存在するが、title のセクションの DLID を持つアンカー行がその文書にも指定ディレクトリ内の他の文書にも無いことで判定する（§1、要件 D-033）。
