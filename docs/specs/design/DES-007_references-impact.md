# DES-007 参照検査と[変更影響候補の通知] DLID-37c14e215jqb

<a id="sec-1"></a>

## 1. [正式な参照]と検査根拠 DLID-pnrn5dyy7z05

[正式な参照]は、Markdown のリファレンスリンクの定義のうち、title の最後の語が[DLID]であるものから抽出する（要件 [D-032][req-001-d]）。

- title を空白で区切り、最後の語を参照先の[DLID]とする。
- 最後の語の直前の語が title の記録語の形（要件 [D-058][req-001-d]）のとき、それを title に記録した[内容ハッシュ]として保持する。
- 直前の語が無い、または記録語の形でないときは、「記録なし」として保持する。
- 参照先は文書または[セクション ID]である。

参照元 ID、記載位置、参照先 ID、リンク定義の相対パスを別々に保持する。[文書 ID]が同じキーにあるか、保存済み[ToC]・管理状態にあるかは、現在の参照の正しさの判定に使わない。title に[DLID]の無いリンク、インラインリンク、ファイル名、自然言語の言及は[正式な参照]に含めない（要件 [D-032][req-001-d]）。[DLID]入りの title を持つインラインリンクは、`check-links` が報告する（要件 [FR-016][req-005-fr-016]）。

script は参照元からリンク定義の相対パスを解決し、指定された**ディレクトリ**を実走査する。title の[DLID]が文書の[DLID]なら候補文書の frontmatter の `doc_link_id` と、[セクション ID]なら候補文書の中の見出しの行の末尾の[DLID]と照合する。[セクション ID]は、それを含む文書を所属文書とし、所属文書のパスをリンク先パスと比べる。リンク先のフラグメント（`#…`）は参照先の同一性の判定に使わない。結果は「一致」「同ディレクトリ内の別パスに同 ID がありパス不一致」「指定ディレクトリ内に不在」のいずれか。指定ディレクトリ自体が存在しない場合と、ディレクトリを読めない場合も「不在」とする（要件 [D-025][req-001-d]）。指定ディレクトリの名前が固定の除外の名前（`build`・`vendor` など）、またはその配下のときも、そのディレクトリを走査する。参照が明示しているためで、固定の除外は[Index 対象リスト]を作る走査と展開に限る。走査の中で見つけた、その配下の固定の除外の名前のディレクトリは走査しない（要件 [D-055][req-001-d]）。「一致」の場合、フラグメントがあれば別に到達先を確かめる。フラグメントを参照先文書の明示アンカー（`<a id>`）または見出しから生成されるアンカー（[DES-008 §2][des-008-sec-2]）に解決し、解決できない場合は「フラグメント不一致」とする。title が[セクション ID]なら、フラグメントがそのセクションの見出しのアンカーに解決しない場合（明示アンカーに解決した場合を含む）も「フラグメント不一致」とする（要件 [FR-009][req-005-fr-009]）。フラグメント不一致には、その[DLID]のセクションへ届く現在のアンカーを添える。結果は検査ディレクトリ・時点・証拠を伴う。同一 ID が複数見つかった場合は一意の現在パスを推定せず、重複診断にする。参照先が[ToC 識別キー]の対象外でも、この走査を省略しない。

パス不一致の修正先は、実走査で同じ ID の実体を一意に確認した場合にだけ通知する。指定ディレクトリの外へ移動した文書は、そのディレクトリの検索では発見できない。保存済みパスや別キーの情報から「現在パス」を推測して確定値として返さない（要件 [FR-010][req-005-fr-010]）。指定ディレクトリ内不在とパス不一致は[ToC]確定を妨げない（要件 [D-025][req-001-d]）。

title に[DLID]の無いリンク（`link_without_dlid`）には、title に書く値を添える（要件 [FR-016][req-005-fr-016]・[AC-032][req-005-ac-032]）。値は `<内容ハッシュ> DLID-…` の形で、実走査で読んだ参照先の現物から決める。保存済みの[ToC]・管理状態の記録は使わない（`resolve-dlid` が返す記録とは異なり、検査時点の現物の値である）。リンクの種別ごとの値は次のとおり。

- フラグメントが無いリンク、またはフラグメントが明示アンカーに解決するリンク: 参照先文書の[文書 ID]と、文書全体の[内容ハッシュ]
- フラグメントが見出しから生成されるアンカーに解決するリンク: その見出しの[セクション ID]と、そのセクションの[内容ハッシュ]
- フラグメントがどちらにも解決しないリンク、または参照先の文書を読めないリンク: 値を添えず、添えない理由を添える
- インラインリンク: 同じ規則で値を添える。リファレンスリンクの定義への書き換えと参照ラベルは、[プロジェクト管理 AI]が決める

[内容ハッシュ]の算出は[DES-008 §3][des-008-sec-3]の規則に従い、`check-impact` と同じ部品を使う。値を文書へ書くのは[プロジェクト管理 AI]であり、doc-link は書かない（要件 [D-031][req-001-d]・[D-042][req-001-d]）。

## 2. 逆参照と影響候補 DLID-9chw5bzdm8zm

逆参照は、走査済みの参照元から作る。

- 参照元を走査したキー・対象指定・時点を、結果に結び付ける。
- 対象内の参照元が見つからないことを、世界全体に参照元がないことと同一視しない（要件 [FR-014][req-005-fr-014]）。
- 参照先は、検査するキーの[確定 ToC]に入っている文書とセクションに限る。

参照ごとに、title に記録した[内容ハッシュ]と、参照先の[現在ハッシュ]を比べる。

- [確定 ToC]が最新であることが前提である。最新なら、[ToC]の[反映済みハッシュ]は現物の[現在ハッシュ]と等しい。
- 参照先が文書の[DLID]なら、その[文書 ID]の[反映済みハッシュ]を、参照先の[現在ハッシュ]として使う。文書内のどこが変わっても異なる。
- 参照先が[セクション ID]なら、[確定 ToC]のそのセクションのセクションエントリにある、セクション単位のハッシュを、参照先の[現在ハッシュ]として使う。範囲は要件 [D-033][req-001-d] に従う。
- 現物からは計算しない。
- 記録と[現在ハッシュ]を、記録語の形に合わせて完全一致で比べる（[DES-008 §3][des-008-sec-3]、要件 [D-058][req-001-d]）。
- 一致しない参照を、影響候補として列挙する。
- title に記録した[内容ハッシュ]が「記録なし」の参照も、影響候補として列挙する。
- 見出しはセクションの範囲に含まれるので、見出しの変更も、セクションエントリのハッシュを異ならせる。
- 所属文書だけが変わり、[内容ハッシュ]が同じセクションは、異ならない。
- 参照先の[文書 ID]または[セクション ID]が[確定 ToC]に無い（削除・移動された）参照は、比べず、影響候補にしない。`check-links` が、存在しないセクションへの参照・パス不一致として検出する。

間接の参照元は列挙しない。参照元を直すとその参照元が次の検出で変更として現れるので、間接的な影響は 1 段ずつ検出される（要件 [D-043][req-001-d]）。未決の限定を根拠に候補を勝手に除外しない。

## 3. [変更影響候補の通知] DLID-mjeyc85ak4w3

参照元は[確定 ToC]の参照関係から取るので、[ToC]が現物を反映していない場合は変更影響候補を返さず、検査結果を返す（[DES-010 §1.2][des-010-sec-1-2]）。

- script は、参照元を[確定 ToC]の参照関係から取る。
- script は、title の記録を参照元の現物から読み、参照先の[現在ハッシュ]（[確定 ToC]に記録したハッシュ）と比べて、異なる参照を特定する。
- [確定 ToC]に保存した title の記録は使わない。記録だけを書き換えても[内容ハッシュ]は変わらず、[ToC]が古いと判定されないためである（要件 [D-039][req-001-d]）。
- Skill は、次を[プロジェクト管理 AI]へ返す。
  - 変更された[文書 ID]・箇所・[現在ハッシュ]
  - title に記録した[内容ハッシュ]
  - 参照元[文書 ID]・箇所・参照記述
  - 検査範囲
- 参照元がない場合は、「走査した範囲では見つからない」という事実だけを返す。
- script が失敗したときは、エラーの JSON を返し、通知しない。

doc-link は参照元の修正要否を判断せず、根拠や修正案を生成せず、本文・リンクを編集しない。修正要否の判断と修正は通知を受けた[プロジェクト管理 AI]が行う。

通知の状態は、doc-link が持たない（要件 [D-038][req-001-d]）。

- doc-link は、何も書き換えない。
- title の[内容ハッシュ]を書くのは、[プロジェクト管理 AI]である。
- [プロジェクト管理 AI]が参照元を確かめて直し、title の[内容ハッシュ]を参照先の[現在ハッシュ]へ書き換えるまで、同じ参照を毎回返す（要件 [FR-015][req-005-fr-015]）。
- 書き換えは、参照元ごとに、変更箇所と参照元の記述を読んで確かめた参照だけに行う。読まずに一括で書き換えない。確かめた結果（修正の要否と根拠）は、報告に残す（要件 [FR-015][req-005-fr-015]、[DES-010 §3.7][des-010-sec-3-7]）。
- title の[内容ハッシュ]を書き換えても、参照元の[内容ハッシュ]は変わらない（要件 [D-039][req-001-d]、[DES-008 §3][des-008-sec-3]）。

## 4. 不整合検査 DLID-wpjybjaee1df

不整合検査は ID 欠落・重複、壊れた参照、title に[DLID]の無いリンク、パス不一致、[ToC]と現物の差、title の記録と参照先の[現在ハッシュ]が異なる参照を一覧化する操作として扱う。検査内容ごとに `check-dlid`、`check-links`、`check-toc`、`check-impact` の SKILL に分ける（[DES-010][des-010]）。検査は管理状態を書き換えない。ID の付与は DLID 付与操作だけが行うので、検査は[Index 対象文書]を変更しない（要件 [D-035][req-001-d]）。検出事項に重要度の分類は設けない。検出事項ごとの扱い（[ToC]の確定を妨げるか、検出後の作業）は、要件 [D-025][req-001-d]・[D-036][req-001-d] と[DES-010][des-010]が定める。「存在しないセクション」は、リンク先パスの文書は存在するが、title の[セクション ID]を行の末尾に持つ見出しがその文書にも指定ディレクトリ内の他の文書にも無いことで判定する（§1、要件 [D-033][req-001-d]）。
