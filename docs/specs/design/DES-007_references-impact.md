# DES-007 参照検査と[変更影響候補の通知]

**状態**: 承認済み\
**更新日**: 2026-11-02\
**根拠**: [参照と変更通知の要件][req-005]

<a id="sec-1"></a>

## 1. [正式な参照]と検査根拠

[正式な参照]は、Markdown のリンクのうち title の最後の語が[DLID]であるものから抽出する（要件 D-032）。参照先は文書または[セクション ID]である。参照元 ID、記載位置、参照先 ID、リンク定義の相対パスを別々に保持する。[文書 ID]が同じキーにあるか、保存済み[ToC]・管理状態にあるかは、現在の参照の正しさの判定に使わない。title に[DLID]の無いリンク、ファイル名、自然言語の言及は[正式な参照]に含めない（要件 D-032）。

script は参照元からリンク定義の相対パスを解決し、指定された**ディレクトリ**を実走査する。title の[DLID]が文書の[DLID]なら候補文書の frontmatter の `doc_link_id` と、[セクション ID]なら候補文書の中の見出しの行の末尾の[DLID]と照合する。[セクション ID]は、それを含む文書を所属文書とし、所属文書のパスをリンク先パスと比べる。リンク先のフラグメント（`#…`）は参照先の同一性の判定に使わない。結果は「一致」「同ディレクトリ内の別パスに同 ID がありパス不一致」「指定ディレクトリ内に不在」のいずれか。指定ディレクトリ自体が存在しない場合と、ディレクトリを読めない場合も「不在」とする（要件 D-025）。「一致」の場合、フラグメントがあれば別に到達先を確かめる。フラグメントを参照先文書の明示アンカー（`<a id>`）または見出しから生成されるアンカー（[DES-008 §2][des-008-sec-2]）に解決し、解決できない場合は「フラグメント不一致」とする。title が[セクション ID]なら、フラグメントがそのセクションの見出しのアンカーに解決しない場合（明示アンカーに解決した場合を含む）も「フラグメント不一致」とする（要件 FR-009）。フラグメント不一致には、その[DLID]のセクションへ届く現在のアンカーを添える。結果は検査ディレクトリ・時点・証拠を伴う。同一 ID が複数見つかった場合は一意の現在パスを推定せず、重複診断にする。参照先が[ToC 識別キー]の対象外でも、この走査を省略しない。

パス不一致の修正先は、実走査で同じ ID の実体を一意に確認した場合にだけ通知する。指定ディレクトリの外へ移動した文書は、そのディレクトリの検索では発見できない。保存済みパスや別キーの情報から「現在パス」を推測して確定値として返さない（要件 FR-010）。指定ディレクトリ内不在とパス不一致は[ToC]確定を妨げない（要件 D-025）。

## 2. 逆参照と影響候補

逆参照は走査済みの参照元から作る。対象の変更前後の[内容ハッシュ]と、参照元を走査したキー・対象指定・時点を結び付ける。対象内の参照元が見つからないことを、世界全体に参照元がないことと同一視しない（要件 FR-014）。[通知済みハッシュ]はキーに依存しないので、対象文書があるキーから離脱しても除去しない。どのキーにも所属しなくなった文書の[通知済みハッシュ]は除去する（要件 D-046）。

[内容ハッシュ]が変わった文書とセクションについて、直接参照の候補を列挙する。[内容ハッシュ]は原文のハッシュなので（要件 D-039）、本文・見出し・リンクの表示文字列・リンク先・title の[DLID]のどれが変わっても変更になる。[セクション ID]を参照する参照元には、そのセクションの範囲に変更があった場合に通知する（要件 D-033）。文書の[DLID]を参照する参照元には、文書内のどこが変わっても通知する。

セクションは、[セクション ID]ごとに[通知済みハッシュ]と比べる（要件 FR-012）。見出しはセクションの範囲に含まれるので、見出しの変更は本文の変更と同じく[内容ハッシュ]の変更になる。

| 区別 | 判定                                                   | 通知                                                                                        |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 追加 | [通知済みハッシュ]に無い[DLID]が[ToC]に現れた          | 新規の文書と同じく新規として通知し、通知の後に[通知済みハッシュ]を作る（要件 REQ-003 §7.5） |
| 変更 | 同じ[DLID]の[内容ハッシュ]が[通知済みハッシュ]と異なる | そのセクションを参照する参照元へ通知する                                                    |

[ToC]に無くなった[セクション ID]の[通知済みハッシュ]は、通知せずに除去する。削除・移動されたセクションを指すリンクは、`check-links` が存在しないセクションへの参照・パス不一致として検出する。所属文書だけが変わり[内容ハッシュ]が同じセクションは、変更として通知しない。

間接の参照元は列挙しない。参照元を直すとその参照元が次の検出で変更として現れるので、間接的な影響は 1 段ずつ検出される（要件 D-043）。未決の限定を根拠に候補を勝手に除外しない。

## 3. [変更影響候補の通知]と[通知済みハッシュ]

参照元は[確定 ToC]の参照関係から取るので、[ToC]が現物を反映していない場合は変更影響候補を返さず、[ToC]の再構築を案内する（[DES-010 §1.2][des-010-sec-1-2]）。script は、[通知済みハッシュ]と現物の[内容ハッシュ]から[未通知の変更]を特定し、確定済みの参照関係から把握できる参照元を列挙する。Skill は変更[文書 ID]・箇所・[内容ハッシュ]、参照元[文書 ID]・箇所・参照記述、および検査範囲を[プロジェクト管理 AI]へ返す。参照元がない場合も「走査した範囲では見つからない」という事実だけを返し、その変更を「参照元なし」の組として記録する。後から参照元が加わった場合、その参照元との組はまだ通知済みでないので通知対象になる。

doc-link は参照元の修正要否を判断せず、根拠や修正案を生成せず、本文・リンクを編集しない。修正要否の判断と修正は通知を受けた[プロジェクト管理 AI]が行う。

[ToC]の確定だけでは[通知済みハッシュ]を進めない（要件 D-038）。script は、通知する組の[通知済みハッシュ]を通知する[内容ハッシュ]へ進めてから、通知の全体を結果の JSON として返す。[通知済みハッシュ]を進められなかった場合はエラーの JSON を返し、通知しない。[通知済みハッシュ]は旧値のままなので、次の実行で同じ変更を通知する。[プロジェクト管理 AI]の判断や修正の結果は、[通知済みハッシュ]を進める条件にしない（要件 FR-015）。[通知済みハッシュ]は (対象の文書または[セクション ID], 参照元[文書 ID]または「参照元なし」) の組ごとに保持し、走査に使ったキーには依存しない（要件 U-010）。参照元が新たに Index 対象へ加わった場合、その組がまだ通知済みでなければ、対象の[内容ハッシュ]が変わっていなくても通知対象にする。

## 4. 不整合検査

不整合検査は ID 欠落・重複、壊れた参照、title に[DLID]の無いリンク、パス不一致、[ToC]と現物の差、[未通知の変更]を一覧化する操作として扱う。検査内容ごとに `check-dlid`、`check-links`、`check-toc`、`check-impact` の SKILL に分ける（[DES-010][des-010]）。管理状態を書き換えるのは、通知を返すときに[通知済みハッシュ]を進める `check-impact` だけである（§3）。ID の付与は DLID 付与操作だけが行うので、検査は[Index 対象文書]を変更しない（要件 D-035）。検出事項に重要度の分類は設けない。検出事項ごとの扱い（[ToC]の確定を妨げるか、検出後の作業）は、要件 D-025・D-036 と[DES-010][des-010]が定める。「存在しないセクション」は、リンク先パスの文書は存在するが、title の[セクション ID]を行の末尾に持つ見出しがその文書にも指定ディレクトリ内の他の文書にも無いことで判定する（§1、要件 D-033）。
