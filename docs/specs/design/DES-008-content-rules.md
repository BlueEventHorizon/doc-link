**更新日**: 2026-10-27\
**根拠**: [ID 要件][req-002]、[ToC 要件][req-003]、[参照要件][req-005]

## 1. 文書 ID の読取りと書込み

frontmatter の `doc_link_id` から、システム発行の `DLID-` 付き固定長 ID として認識できる単一文字列を読む。欠落・空・null・解析不能・認識不能はいずれも「文書 ID が存在しない」と分類し、形式不正という別分類を作らない。「文書 ID が存在しない」と判定した文書には ID 付与操作が発行・保存し（要件 D-035）、認識済みの発行済み ID を本文やパスから再計算しない。発行値は `secrets` による 60 ビット乱数を小文字の Crockford Base32 で 12 文字に表したものとする（決定: U-001、要件 D-028）。認識は大文字小文字を区別し、`DLID-` と小文字 12 文字の完全一致だけを ID とする。大文字に変えた値は認識できない値として「文書 ID が存在しない」に分類する。この区別は DLID の照合に限る。リファレンスリンクのラベルの照合は CommonMark の規則（大文字小文字を区別しない）に従い、解決したリンクの title に含まれる DLID を D-028 に従って照合する。

既存 frontmatter と本文を保ち、書き込むのは DLID だけとする。位置は frontmatter の `doc_link_id`、見出し直前のアンカー行 `<a id="DLID-…"></a>`（直後に空行を置く。直前の行が段落の行なら、アンカー行が段落に取り込まれないよう直前にも空行を置く。CommonMark では、アンカー行は HTML ブロックではなく、二つの `html_inline` だけから成る段落として解析される）、参照リンクの title 属性（既存の title があれば末尾に空白区切りで追加し、囲み記号は変えない）に限る。コードブロック・HTML ブロック内には書き込まない。書き込み後に markdown-it-py で再解析し、差分が指定した位置の DLID だけであることを検証し、それ以外の差分があれば書き込みを取り消して報告する（要件 D-031）。frontmatter を解析できない文書には書き込まず、報告する。

<a id="sec-2"></a>

## 2. Markdown 参照と位置

Markdown の構造（コードブロック、見出し、リンクの URL・title、HTML ブロック）は markdown-it-py（`>=4.0`、CommonMark 準拠）で解析し（script は `uv run` で実行し、依存を PEP 723 で宣言する）、独自の正規表現でブロック構造を判定しない。markdown-it-py はリンクの行内位置を持たないため、文書への書き込みは行単位の文字列操作で行い、書き込み後に再解析して意図したリンク・見出しだけが変わったことを検証する。

インラインリンクとリファレンスリンクの定義の title を解析し、最後の語が DLID のものを正式な参照として、DLID・記載パス・参照元の位置を取得する（要件 D-032）。セクションの DLID は、`<a id="DLID-…">` と `</a>` の二つの `html_inline` だけから成る段落で、次のブロックが見出しであるものから取得し、その見出しのセクションの DLID とする。範囲は、その見出しから同じ階層以上の次の見出しの直前までとする（要件 D-033）。相対パスは参照元ファイルの配置を基準に解決する。参照先 ID と物理パスは別の値であり、片方の変更をもう片方へ自動伝播しない。未定義ラベル、重複定義、URL、フラグメント、エスケープ、大小文字の扱いはテスト可能な解析規則として実装前に確定する。移行時には、見出し文字列から生成されるアンカーを GitHub と同じ規則で解決して参照先の見出しを特定する。特定できないリンクには DLID を追加せず報告する（要件 D-034）。

<a id="sec-3"></a>

## 3. 比較値とハッシュ

内容ハッシュは、原文の UTF-8 のバイト列の SHA-256 とする（要件 D-039）。正規化や管理用の記述の除去は行わない。セクションの内容ハッシュは、そのセクションの範囲（§2）の原文の SHA-256 とする。ID の発行値は内容ハッシュとは独立する。ToC に反映した内容ハッシュ、現在の現物から計算した内容ハッシュ、変更影響候補の報告まで完了した処理済み比較基準を混同しない。

入力文字列から内容ハッシュまでの再現可能なテストベクトルを作る。本文、見出し、リンクの表示文字列・リンク先・title、DLID の追加のどれでも内容ハッシュが変わること、あるセクションの範囲の外だけを変えた場合にそのセクションの内容ハッシュが変わらないことを試す。

<a id="sec-4"></a>

## 4. AI 生成フィールド

タイトルが機械取得できない場合の生成方法と、目的・内容概要・適用作業・キーワードの生成入力を定める。生成 AI に渡す上限はフィールド別の `L` のみとする。script の検証器は `H = floor(L × 1.3)` を用い、`L` 超・`H` 以下を受理し、`H` 超を拒否する。生成 AI が参照するプロンプト・ルール・再試行メッセージに `H` や余白の存在を含めない。`L` の値と文字数の数え方は要件 D-044 に従う。配列のフィールドは要素数を `L`・`H` で検証する。検証器のエラーを生成 AI へ戻す場合も実際の拒否境界を開示しない。
