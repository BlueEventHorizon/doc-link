# DES-008 Markdown 解析・比較値・生成情報の規則 DLID-mmbyse75p9rr

<a id="sec-1"></a>

## 1. [文書 ID]の読取りと書込み DLID-cf1n0ndmf0fe

frontmatter の区切りは次のように判定する。文書の先頭の空行を読み飛ばし、前後の空白を除くと `---` になる最初の行で始まり、次の同じ行で閉じる。閉じる行が無い文書は、frontmatter が無いものとして読む。frontmatter の中身は、最上位のキーだけを読む最小限の解析で読み、YAML の構文の誤りで frontmatter 全体を読めなくすることはしない。

frontmatter の `doc_link_id` から、システム発行の `DLID-` 付き固定長 ID として認識できる単一文字列を読む。欠落・空・null・スカラでない値・認識不能はいずれも「[文書 ID]が存在しない」と分類し、形式不正という別分類を作らない。「[文書 ID]が存在しない」と判定した文書には DLID 付与操作が発行・保存し（要件 [D-035][req-001-d]）、認識済みの発行済み ID を本文やパスから再計算しない。発行値は `secrets` による 60 ビット乱数を小文字の Crockford Base32 で 12 文字に表したものとする（要件 [D-028][req-001-d]）。認識は大文字小文字を区別し、`DLID-` と小文字 12 文字の完全一致だけを ID とする。大文字に変えた値は認識できない値として「[文書 ID]が存在しない」に分類する。この区別は[DLID]の照合に限る。リファレンスリンクのラベルの照合は CommonMark の規則（大文字小文字を区別しない）に従い、解決したリンクの title の最後の語の[DLID]を [D-028][req-001-d] に従って照合する。

既存 frontmatter と本文を保ち、書き込むのは[DLID]だけとする。ただし、frontmatter を新設するときは、`---`・`doc_link_id: <DLID>`・`---` の 3 行の後に、文書の先頭の行が空行でなければ空行を 1 行足す（要件 [D-051][req-001-d]）。位置は frontmatter の `doc_link_id` と、見出しの行の末尾に限る（要件 [D-031][req-001-d]・[D-033][req-001-d]）。見出しには、見出しのテキストの末尾に空白 1 つで区切って[DLID]を置く（例: `## 見出し DLID-…`）。ATX 見出しに閉じの `#` の列があればその前に置き、setext 見出しはテキストの最後の行の末尾に置く。どちらも CommonMark で見出しのテキストに含まれる位置である。HTML、リンク、リンクの title、本文には書き込まない。コードブロック・HTML ブロック内には書き込まない。書き込み後に markdown-it-py で再解析し、差分が指定した位置の[DLID]だけであることを検証し、それ以外の差分があれば書き込みを取り消して報告する（要件 [D-031][req-001-d]）。閉じる行が無い文書には書き込まず、報告する。原本への書き込みは、一時ファイルに書いてから `os.replace` で置き換え、元のファイルの権限を保つ。書き込み先がシンボリックリンクのときは、リンクを通常のファイルで置き換えず、リンクの実体を置き換える。実体がプロジェクトの外にあってもよい（要件 [D-049][req-001-d]）。

## 2. Markdown 参照と位置 DLID-7d2f9n4a3vry

Markdown の構造（コードブロック、見出し、リンクの URL・title、HTML ブロック）の解析は、次のとおりとする。

- markdown-it-py（CommonMark 準拠）で解析する。
- 独自の正規表現でブロック構造を判定しない。
- script は `uv run` で実行し、依存を PEP 723 で宣言する。

markdown-it-py はリンクの行内位置を持たないため、文書への書き込みは行単位の文字列操作で行い、書き込み後に再解析して意図した見出しだけが変わったことを検証する。

リファレンスリンクと見出しは、次のとおり解析する。

- リファレンスリンクの定義の title を解析し、最後の語が[DLID]のものを[正式な参照]とする。取得するのは、[DLID]・title に記録した[内容ハッシュ]・記載パス・参照元の位置である（要件 [D-032][req-001-d]）。
- インラインリンクは[正式な参照]としない。
- 見出しのテキストの最後の語が[DLID]であるものから、その見出しの[セクション ID]を取得する。
- セクションの範囲は、その見出しから同じ階層以上の次の見出しの直前までとする（要件 [D-033][req-001-d]）。
- 相対パスは参照元ファイルの配置を基準に解決する。
- 参照先 ID と物理パスは別の値であり、片方の変更をもう片方へ自動伝播しない。

リンクの解析は次の規則に従う。

規則 1〜5 は CommonMark 仕様（Links 節、Link reference definitions 節）の規則であり、markdown-it-py の解析結果をそのまま使い、独自に判定しない。各規則は markdown-it-py で同じ結果になることをテストで確かめる。

1. 定義の無いラベルを使ったリンクは、リンクにならず文字列として扱われる。
2. 同じラベルの定義が複数あれば、最初の定義を使う。
3. ラベルは、前後の空白を除き、続く空白を 1 つにまとめ、Unicode の case fold を行ってから照合する。全角と半角は別の文字である。
4. title と href は、バックスラッシュのエスケープと文字参照を展開した後の値を使う。
5. 宛先に空白を含むなど、リンクとして成立しない書き方は参照として扱わない。
6. スキームの付いた宛先（`https:` など）は、title に[DLID]があっても参照として扱わない。
7. markdown-it-py は href のパス部分とフラグメントをパーセント符号化して返す。どちらもデコードしてから解決する。
8. 宛先は `#` の前で参照先の文書を、後で見出しを特定する。`#` の前が空なら参照元の文書自身を指す。
9. 画像（`![…](…)`）は参照として扱わない。
10. autolink と HTML の `<a>` は title を持たないので、[正式な参照]にならない。このこともテストで確かめる。

見出しから生成されるアンカーは、要件 [D-048][req-001-d] の規則で作る。規則は GitHub の規則（github-slugger v2.0.0）と同じ結果になるよう、次のとおり定める。

- アンカーを作る見出しのテキストは、強調やコードなどの Markdown の記号を除いた表示文字列とする。行末の[セクション ID]を含む。
- 英字を小文字にする。
- 次の文字を取り除く。Unicode の Alphabetic 特性を持つ文字は取り除かない。
  - Unicode の一般カテゴリが、Other_Number、Close_Punctuation、Final_Punctuation、Initial_Punctuation、Open_Punctuation、Other_Punctuation の文字
  - 同じく、Dash_Punctuation の文字。ただし、半角ハイフン `-` は残す。
  - 同じく、Symbol 全般、Control、Private_Use、Format、Unassigned の文字
  - 同じく、Separator の文字。ただし、半角空白は残す。
- 半角空白を `-` に置き換える。
- 同じ文書の中で同じアンカーが重複するときは、2 つ目以降に `-1`、`-2` の順に連番を付ける。

このアンカーは、`check-links` がフラグメントの到達先を確かめるとき（[DES-007 §1][des-007-sec-1]）と、[DLID]の解決がセクションへ届くアンカーを返すときに使う。doc-link はこのアンカーを文書に書き込まず、リンクの特定や書き換えにも使わない（要件 [D-034][req-001-d]、[D-042][req-001-d]）。

## 3. 比較値とハッシュ DLID-2f452e4mna91

[内容ハッシュ]は、原文の UTF-8 のバイト列の SHA-256 とする（要件 [D-039][req-001-d]）。

- 正規化はしない。
- 表記は、小文字の 16 進 64 文字とする。
- title に記録する値は、先頭の 12 文字とする（要件 [D-058][req-001-d]）。記録と[現在ハッシュ]の比較は、[現在ハッシュ]の先頭 12 文字で行う。[ToC]に反映する値は、64 文字のままとする。
- [正式な参照]（リンクの定義で、title の最後の語が[DLID]のもの）の title は、除いて計算する。
- 除くのは、リンク先と title の間の空白から、title の閉じ（`"`・`'`・`)`）までである。
- title の無い定義と、除いたあとの文字列が同じになる。
- ほかのバイトは変えない。インラインリンクの title と、[DLID]で終わらない title は除かない。
- 原文で、定義の末尾にこの形（空白、開き、title、閉じ、行末の空白）を見つけられないときは、その定義からは何も除かない。別の位置を推測して除かない。
- 除くのは、title に[内容ハッシュ]や[DLID]を書いても、書き換えても、参照元の[内容ハッシュ]を変えないためである。
- title に書いた参照先の[DLID]の変更（参照の付け替え）は、[内容ハッシュ]に頼らず、参照記述の違い（[DES-005 §3][des-005-sec-3]）として検出する。

セクションの[内容ハッシュ]は、そのセクションの範囲（§2）の原文の SHA-256 とする。ID の発行値は[内容ハッシュ]とは独立する。[ToC]に反映した[内容ハッシュ]、現在の現物から計算した[内容ハッシュ]、参照元の title に記録した[内容ハッシュ]を混同しない。

入力文字列から[内容ハッシュ]までの再現可能なテストベクトルを作る。本文、見出し、リンクの表示文字列・リンク先、見出しの[DLID]の追加のどれでも[内容ハッシュ]が変わること、title の[内容ハッシュ]を書き換えても、title の[DLID]を書き換えても、title を初めて書き加えても、[内容ハッシュ]が変わらないこと、title の形（`"`・`'`・`)`）が違っても同じになること、互いを参照する 2 つの文書で、記録を書き換えても互いの[内容ハッシュ]が変わらないこと、あるセクションの範囲の外だけを変えた場合にそのセクションの[内容ハッシュ]が変わらないことを試す。

## 4. [AI 生成フィールド] DLID-7et3ryybpbag

タイトルは文書の最初の H1 見出しのテキストから、行末の[セクション ID]を除いたものとする。H1 が無い文書のタイトルは `toc-updater` が生成する。目的・内容概要・適用作業・キーワード、および生成するタイトルは、`toc-updater` が対象文書の本文を読んで生成する（[DES-010 §4][des-010-sec-4]）。[情報生成 AI]に渡す上限はフィールド別の `L` のみとする。script の検証器は `H = floor(L × 1.3)` を用い、`L` 超・`H` 以下を受理し、`H` 超を拒否する。[情報生成 AI]が参照するプロンプト・ルール・再試行メッセージに `H` や余白の存在を含めない。`L` の値と文字数の数え方は要件 [D-044][req-001-d] に従う。配列のフィールドは要素数を `L`・`H` で検証する。要素数の下限は、内容概要 5、適用作業 1、キーワード 5 とし、下回れば拒否する。生成する値は、文書の言語にかかわらず英語で書く。検証器のエラーを[情報生成 AI]へ戻す場合も実際の拒否境界を開示しない。
