# DES-009 要件対応と設計検証

**状態**: Draft 0.1\
**更新日**: 2026-10-27\
**根拠**: [要件書群][req-001]、[状態モデル][des-004]

<a id="sec-1"></a>

## 1. テストの規範

状態を持つ処理は [DES-004 の遷移表][des-004] を唯一の許可遷移一覧とする。P-01〜P-03、B-01〜B-09、E-01〜E-07、N-01〜N-05 の各行について、元状態・イベント・ガード成立で指定した次状態と効果になることを試す。同じ元状態でガード不成立、表にないイベント、別状態からのイベントを与えたときは拒否し、公開版と比較基準が変わらないことを試す。Mermaid 図は表と同じ遷移を可視化するだけであり、図にない暗黙の遷移を認めない。

参照先の不在は候補確定ガードを不成立にしない（決定: U-020）。指定ディレクトリ内不在・指定ディレクトリ自体の不在・ディレクトリを読めない場合がいずれも「不在」として記録され、確定することを試す。途中中断、再実行、旧確定版保持、部分的に保存済みの ID、複数キーの隔離も状態テストに含める。`check-impact` が比較基準を進められなかった場合はエラーを返して報告せず、旧比較基準のまま次回に同じ変更を報告することを試す。参照元が無い変更が「参照元なし」として記録され、再報告されないこと、後から参照元が加わるとその組が報告されることを試す。二つのキーに所属する文書が一方のキーから離脱しても比較基準が残ること、全キーから離脱すると除去されることを試す。セクションの追加と変更が区別して報告され、ToC に無くなったセクションの比較基準が通知なしに除去されることを試す。

状態遷移でない決定論的処理は別に単体テストを持つ。対象指定の展開、Markdown 解析、ID 認識・発行・重複、パス解決、ディレクトリ走査結果の分類、比較値、AI 出力検証、ToC 候補整合性を対象にする。

## 3. 横断シナリオ

1. 初回：ID 付与操作 → 対象指定 → ID 確認 → 変更集合 → 必要情報 → 参照実走査 → ToC 確定 → 検索可能。
2. 移動：同じ ID・同じ内容でパスだけ変更し、要約を再生成せず ToC の現在パスを更新する。参照元の古いパスは自動修正しない。
3. 内容変更：ToC 確定後も変更影響候補の報告が未完了なら比較基準は旧値。次回に要約を再生成せず報告を続行する。
4. 失敗：AI 生成・参照走査・候補確定・通知の各失敗位置で旧公開版、旧比較基準の扱いを区別する。それまでに確定した文書情報行は戻さず、ToC が旧版のキーからも最新の文書情報が見える（要件 D-024）。
5. 複数キー：同一 ID が A と B に所属し、A の更新・離脱が B の ToC を書き換えない。同じ ID・内容ハッシュの検証済み情報を再利用できる場合、B への追加だけで AI 要約を再生成しない。B は A と同じ文書情報行を参照するため表示は一致し、報告済み比較基準は (対象 ID, 参照元 ID) の組で判定する（決定: 旧 R-001／R-002）。
6. 範囲外参照：管理対象外でも指定ディレクトリを実走査し、結果に範囲・時点を付ける。対象範囲外への移動先は推測しない。
7. 後からの参照：ID 付与操作が全見出しにセクションの DLID を付けた文書の見出しへ、別の文書から新しくリンクを書く。ID 付与操作が参照元のリンクの title にだけ DLID を加え、参照先の文書を書き換えないことを確かめる（要件 D-033）。ID 付与操作の後に追加した見出しへのリンクは、参照先の文書が対象外なら書き込まずに再実行を求める報告になる（要件 D-042）。

## 4. 承認前に決める境界

要件の未決事項は、すべて決定済みである。現時点の設計書は実装着手用の確定仕様ではなく、レビュー前の初稿である。
