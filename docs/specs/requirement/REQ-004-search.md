## 12. 文書検索

### FR-006 文書検索

プラグインは、ユーザーまたは他のスキルから与えられたタスクに関連する文書を検索できること。

検索要求は、`--key <key>` が指定された場合はそのキーの ToC を検索し、キーが省略された場合は予約キー `all` の単体モード ToC を検索すること。索引構築時と検索時で同じ管理キーを指定すれば、同じ管理対象集合を使用できること。

指定されたキーの ToC が存在しない場合、検索を行わず、管理対象指定を用いた初回構築が必要であることを返すこと。既存 ToC がある場合は、検索を実行する前に、その ToC に保存された再解釈可能な管理対象指定を基に現在の対象文書と ToC の状態を検査して、再構築が必要かを判定すること。呼び出し元が更新済みの管理対象指定を同時に渡すインターフェースを設ける場合は、その指定を優先して比較する。再構築が必要な場合は、ユーザーに次のいずれかを選択させること。

- ToC を再構築してから検索する
- ToC を更新せず、既存の ToC のまま検索する

この確認では、再構築の規模として、新規・離脱・パスだけの変更・内容の変更・文書 ID が無い文書・文書 ID が重複する文書の件数と、AI による要約生成が必要な文書の件数を示すこと。要約生成が必要な件数には、同じ内容の検証済み文書情報を再利用できる文書を含めない（D-027）。

権限不足、読み取りエラー、保存済み管理対象指定の解釈不能、管理状態の読取不能などにより再構築要否を判定できない場合は、障害として検索を停止し、判定できなかった対象と原因を返すこと。この場合、既存の ToC のまま検索する選択肢を提示してはならない（D-026）。

既存の ToC のまま検索する場合は、検索結果とともに、ToC が現在の管理対象文書を反映していない可能性を通知すること。この選択によって既存の ToC を現在状態として再確定してはならない。このとき既存の ToC の版から使うのはキー別の索引状態（所属、参照関係、反映済みハッシュ、検査結果）であり、タイトルや要約などの文書情報は文書ごとの最新の内容を用いる（D-024）。

検索結果には少なくとも次を含める。

- 文書 ID
- ToC に記録されているパス
- 関連すると判断した理由
- 必要に応じて該当セクション
- 検索に使用した ToC の状態

## 受け入れ条件案

### AC-019 検索前の ToC 再構築確認

指定キーの ToC が未構築の場合は検索できず、初回構築が必要であることを返すこと。既存 ToC がある場合は、検索要求に管理対象指定が含まれなくても、ToC に保存された指定を再解釈して現在の対象文書を列挙し、再構築要否を検査できること。検索前の検査で再構築が不要と判定された場合は、そのまま検索を実行すること。再構築が必要と判定された場合は、検索前にユーザーへ再構築の規模（変更種別ごとの件数と AI による要約生成が必要な件数）を示して確認し、「ToC を再構築してから検索する」または「既存の ToC のまま検索する」を選択できること。後者を選択した場合は ToC を更新せず、検索結果に ToC の状態と、現在の管理対象文書を反映していない可能性を含めること。再構築要否を判定できない場合は検索を停止し、原因を返すこと。
