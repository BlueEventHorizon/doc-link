## 13. 文書参照とリンク検査

### FR-007 文書 ID を使用した参照

管理対象文書から別の文書を正式に参照する場合、文書 ID を含む規定の記法を使用すること。参照先が参照元と同じ管理キーに所属することや、doc-link の管理対象であることを参照の成立条件にしてはならない。

Markdown では、標準のリンク（インラインリンク、またはリファレンスリンクの定義）の title 属性に参照先の DLID を記載する。title の最後の語が DLID の形式に一致するリンクを正式な参照とする。参照先は文書の DLID でも、[§13.1][req-005-sec-13-1] のセクションの DLID でもよい（D-032）。

```markdown
詳細は[アーキテクチャ原則](../architecture/overview.md "DLID-7k3m9q2x4p8r")を参照する。

詳細は[ID 確認処理][req-id]を参照する。

[req-id]: ../requirement/REQ-002_document-id.md#sec-9-1 "DLID-4m8q2x7k3p9r"
```

この記法では、DLID が参照先の論理的な同一性を表し、リンク先のパスが参照先として指定された物理的な配置を表す。リンクの表示文字列とリンク先は人間が読むためのものとしてそのまま残す。パスが現在も正しいかは実際のディレクトリ検索で検査する。

title に DLID を持たないリンク、ファイル名の記載および自然言語による言及は、正式な参照として扱わない（D-032）。

### FR-009 ID 付きリンクの検査

プラグインは、正式な参照のリンクについて、リンク先のパスから参照先ディレクトリを特定し、実際にそのディレクトリを検索して少なくとも次を検査できること。保存済みの ToC やデータベースの登録有無だけを、現在の参照の正しさの根拠としてはならない。

- リンクの title に DLID が記載されている
- 指定されたディレクトリ内で、参照先文書 ID を持つファイルが見つかる
- リンク先パスが、その文書 ID を持つファイルの現在パスと一致する
- 相対パスが参照元文書から正しく解決できる
- リンク先にフラグメント（`#…`）がある場合、参照先文書の明示アンカーまたは見出しから生成されるアンカーに解決でき、title がセクションの DLID ならそのセクションの見出しに解決する

指定されたディレクトリの検索が正常に完了しても文書 ID が見つからない場合は、「指定されたディレクトリ内に参照先がない」と記録する。これは世界中にその文書が存在しないことを意味しない。指定されたディレクトリ自体が存在しない場合と、ディレクトリを検索できない場合も「指定されたディレクトリ内に参照先がない」と記録する。いずれの結果も ToC の確定を止めない（D-025）。検査結果は検索の完了後に保存する。

### FR-010 参照パス修正情報の通知

文書の移動または改名によりリンク定義の物理パスだけが古くなった場合、プラグインは実際のディレクトリ検索で同じ文書 ID の現在パスを確認できたときに限り、参照元文書 ID、参照元パス、問題箇所、記載されている古いパスおよび確認済みの現在パスを、検出したパス不一致としてプロジェクト管理 AI へ通知できること。現在パスを確認できない場合は、指定ディレクトリ内での不在を通知し、保存済みデータから現在パスを推測して確定値として通知してはならない。

doc-link はリンク定義を更新しないこと。プロジェクト管理 AI がリンク定義を修正した後、doc-link は再検査によってパスの一致を確認できること。

<a id="sec-13-1"></a>

### 13.1 セクション参照

<a id="sec-13-1-1"></a>

#### 13.1.1 課題

Markdown の見出し文字列や自動生成アンカーだけでセクションを識別すると、見出し名の変更によって参照が壊れる。

文書 ID と同様に、パスや表示名から独立したセクション識別が必要かを検討する。

<a id="sec-13-1-2"></a>

#### 13.1.2 候補

#### 案 A: 見出し文字列から生成したアンカーを使う

- 既存 Markdown と親和性が高い
- 見出し名の変更に弱い
- Markdown 処理系によってアンカー生成規則が異なる可能性がある

#### 案 B: すべてのセクションに恒久的なセクション ID を付ける（推奨）

- 追跡は強固になる
- 後から参照されても、参照先の文書へ書き込まずに済む
- ID は ID 付与操作が自動で書くので（D-035）、文書作成者の記述負担は無い
- セクションの分割・統合・複製は、新しい見出しへの発行、壊れた参照の検出（FR-016）、重複の再発行（D-029）で扱える
- 見出しごとにアンカー行が増える

#### 案 C: 外部から参照されるセクションだけに ID を付ける

- 追跡が必要な箇所を安定して識別できる
- 全セクションへの ID 付与を避けられる
- 参照を追加する際に、参照先の文書へアンカー行を書き込む手順が必要になる。ToC 作成後の文書への書き込みになり、参照先の文書が操作の対象外なら書き込めない

案 B を採用する。すべての見出しの直前に `<a id="DLID-…"></a>` の形でセクションの DLID を置く。DLID は文書 ID と同じ形式・同じ発行方式とし、doc-link の ID 付与操作だけが発行して書き込む（D-035）。ID 付与操作は起動されるたびに、対象文書の中でセクションの DLID を持たない見出しすべてに発行する。セクションの範囲は、その見出しから同じ階層以上の次の見出しの直前までとする（D-033）。

## 14. 変更影響候補の列挙と通知

### FR-013 変更影響候補の特定

文書またはセクションの内容ハッシュに変更があった場合、プラグインは管理対象文書から抽出済みの参照関係を逆引きし、把握している参照元文書を機械的に特定できること。参照元が修正を要するかどうかは判定しないこと。

変更影響候補には少なくとも次を含める。

- 変更された文書またはセクション
- 変更前後を識別するハッシュ情報
- 直接参照している文書
- 参照元として列挙した根拠となる参照記述

間接的に依存する文書は列挙しない。参照元が修正されると、その参照元が変更された文書になり、次の検出でその参照元を参照する文書が列挙される。間接的な影響は、この繰り返しで 1 段ずつ検出する（D-043）。

### FR-014 変更影響候補の通知

doc-link は、検出した変更と、その文書またはセクションを参照している文書の一覧を、修正が必要になる可能性がある情報として依頼元のプロジェクト管理 AI へ返せること。少なくとも変更された文書 ID・箇所・比較値、参照元文書 ID・箇所、参照記述、検査した管理範囲を含めること。参照元が見つからない場合も、その結果が走査した範囲に限られることを示すこと。

doc-link は参照元の修正要否を判断せず、理由や修正案を生成せず、参照元文書を変更しないこと。修正要否の判断と実際の文書修正は、通知を受けたプロジェクト管理 AI が行う。

### FR-015 変更報告の管理

同じ変更を見落とさず、報告後の再実行で区別できるように、次の機械的な情報を管理できることを要件候補とする。

- 報告対象となった変更の文書 ID とハッシュ
- 列挙した参照元文書と管理範囲
- 報告の実行結果

プロジェクト管理 AI による修正結果や判断結果は、doc-link の処理済み判定の条件にしない。

<a id="sec-15"></a>

## 15. 不整合検査

### FR-016 不整合検査

プラグインは、外部から与えられた完全な管理対象指定に従って確定した管理対象文書一覧を走査し、少なくとも次の不整合を一覧化できること。

- 文書 ID が存在しない
- セクションの DLID を持たない見出し
- 文書 ID の重複
- セクションの DLID の重複（同じ文書の中を含む）
- 壊れた参照
- `doc_link_id` を持つ Markdown を指しているが、title に DLID の無いリンク（ID 付与操作で DLID を加える対象。D-042）
- 文書 ID と物理パスの不一致
- 存在しないセクションへの参照
- フラグメントが参照先のセクションへ解決しないリンク（見出しの改名後にリンクを直していない場合など）
- ToC と実体ファイルの不一致（新規、離脱、移動、ToC に反映したハッシュと現在の文書のハッシュの違い）
- 参照先として指定されたディレクトリを正常に検索した結果、文書 ID が見つからなかった参照
- 更新済みだが変更影響候補の報告が完了していない文書

## 受け入れ条件案

### AC-003 参照パス不一致の検出

文書移動後、文書 ID は正しいがリンク定義のパスが古い場合、その不一致を検出できること。

### AC-004 参照パス修正情報の通知

実際のディレクトリ検索で同じ文書 ID の現在パスを確認できた場合、古いリンク定義がある参照元文書と問題箇所、古いパスおよび確認済みの現在パスをプロジェクト管理 AI へ通知できること。現在パスを確認できない場合は、指定ディレクトリ内での不在を通知し、保存済みデータによる推測パスを確定値として返さないこと。通知時点では、doc-link が管理対象 Markdown を変更していないこと。

### AC-006 変更影響候補の列挙

文書の内容を変更した場合、管理対象文書のうち、その文書を正式な記法で参照している文書を列挙できること。

### AC-007 セクション単位の限定

参照対象外のセクションだけが変更されたとき、その参照元を影響対象に含めないこと。

### AC-008 管理対象から外れた文書への参照

文書がそのキーの管理対象から外れた場合、その文書 ID を参照している対象内のすべての文書を検出できること。キーから外れたことだけを理由に参照を無効とせず、参照先として指定されたディレクトリを検索して検査状態を決めること。対象範囲外の文書を、そのキーの管理対象文書として追跡しないこと。

### AC-009 変更影響候補の報告

文書の変更を検出した場合、doc-link は把握している参照元と参照記述を機械的に列挙し、修正が必要になる可能性をプロジェクト管理 AI へ報告できること。doc-link が修正不要・修正必要の判断や修正案の作成を行わず、管理対象 Markdown を修正しないこと。

### AC-028 参照先ディレクトリ検索による検証

参照先として指定されたディレクトリを正常に検索し、記載された文書 ID を持つファイルがリンク先パスに存在する場合は、参照を正しいと判定できること。同じディレクトリ内の別パスで見つかった場合はパス不一致を検出できること。DLID とパスが一致していても、フラグメントが title の DLID のセクションへ解決しない場合はフラグメント不一致を検出できること。検索を完了しても見つからない場合は「指定ディレクトリ内に不在」と記録し、世界全体での不存在とは扱わないこと。

参照先ディレクトリを検索できない場合は不在とし、保存済みの ToC やデータベースの情報だけで参照を正しいと判定しないこと。参照先の管理キーへの所属有無によって判定を変えず、検査結果は検索後に保存すること。
