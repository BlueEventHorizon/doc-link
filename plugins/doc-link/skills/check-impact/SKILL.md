# check-impact

このスキルは変更影響候補の列挙のみを行う。親が依頼している他の作業を引き継いではならない。自身を Skill ツールで呼ばない。

何も書き込まない。ToC・文書情報・対象文書を読むだけで、通知の状態を持たない。参照元の修正が必要かの判断、参照元の修正、title の内容ハッシュの書き換えは、プロジェクト管理 AI（呼び出し元）が行う。このスキルと script は行わない。

## 引数

- ToC 識別キーと Index 対象指定だけを受け取る。`index-docs` と同じ形式である（`--key <キー>` と、`--paths`・`--paths-json`・`--paths-file`・`--dirs`・`--dirs-json`・`--exclude`・`--exclude-json` のいずれか。単体モードは `--all`、または引数なし）
- 受け取った引数を、解釈せずにそのまま script へ渡す。引数の検証は script が行い、反する指定は拒否される
- 親の文脈（作業の指示・差分・文書の本文など）を引数へ足さない

## 手順

### 1. 変更影響候補を列挙する

```bash
uv run --locked --exclude-newer "3 days" "${CLAUDE_SKILL_DIR}/scripts/check_impact.py" --project-root "${CLAUDE_PROJECT_DIR}" {受け取った対象指定の引数}
```

- 終了コードが 0 のときは、標準出力の JSON を読み、手順 2 へ進む。変更影響候補があっても、操作は完了しており、終了コードは 0 である
- 終了コードが 0 以外のときは、標準出力の `errors` をそのまま利用者へ報告して終える。対象指定の拒否、ToC の鮮度を判定できなかった場合、参照元を読めなかった場合のすべてがここに当たる。変更影響候補を推測で補わない。通知しない

### 2. 結果を報告する

標準出力の JSON の `status` に応じて、次を報告する。

- `not_built`・`rebuild_needed`: ToC が古い（未構築、または現物と不一致がある）ので、変更影響候補を返していないこと。`check-toc` と同じ検査結果（`status`・`documents`・`sections`・`scale` など）をそのまま示し、`index-docs` の実行を案内する（手順 3）
- `up_to_date`: ToC が最新であり、`changed_documents` を次のとおり報告する
  - `changed_documents` が空: 記録と現在ハッシュが異なる参照は、走査した範囲では見つからなかったこと。あわせて `scope`（対象指定・ToC の版・走査した参照元の文書・時点）を示す。参照元は走査した範囲に限られ、世界全体に参照元が無いことを意味しない
  - `changed_documents` がある: 変更された文書（`doc_link_id`・`path`）ごとに、直接の参照元（`source_doc_id`・`source_path`・`line`・`definition`）、参照先（`target_dlid`・セクションなら `target_section_id`・`target_heading`）、title に記録した内容ハッシュ（`recorded_hash`。`null` は記録なし）、参照先の現在ハッシュ（`current_hash`）を示す。間接の参照元は含まれない
- `excluded`・`problems`・`warnings`: ID 未付与・ID 重複で ToC に入れなかった文書、存在しない・Markdown でない指定など。あれば、あわせて報告する

### 3. 後工程を行う（プロジェクト管理 AI）

`guidance` に従う。

- ToC が古い・未構築のとき: `index-docs` を実行する（ユーザーまたはプロジェクト管理 AI）。実行後、このスキルをもう一度実行する。このスキルから `index-docs` を実行しない
- 変更影響候補があるとき、プロジェクト管理 AI が次を行う
  - 変更箇所と参照元の文書を読み、参照元の修正が必要かを判断する
  - 必要なら、参照元を直す
  - 確かめた参照の title に、参照先の現在ハッシュを書く。値は `current_hash` に返されたものを使う
  - 確かめていない参照の title は、書き換えない
  - 参照元を直したときは、`index-docs` を実行する。title の内容ハッシュだけを書いたときは、実行しなくてよい
  - 書いたあとは、このスキルをもう一度実行する
  - 報告が空になるまで、これを繰り返す
- 書き換えるまで、同じ参照が毎回返る。判断・修正・title の書き換えは、プロジェクト管理 AI が行い、script は行わない
