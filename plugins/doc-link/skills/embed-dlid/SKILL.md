# embed-dlid

このスキルは DLID の付与のみを行う。親が依頼している他の作業を引き継いではならない。自身を Skill ツールで呼ばない。

利用者の文書へ書き込む唯一のスキルである。書き込むのは DLID だけで、frontmatter の `doc_link_id` と、見出しの行の末尾に限る。リンク・リンクの title・見出しのテキスト・本文は書き込まず、書き換えない。起動を書き込みの承認とし、書き込み前に改めて承認を求めない。利用者に確認するのは、重複する DLID の原本の確定だけである。

## 引数

- ToC 識別キーと Index 対象指定だけを受け取る。`index-docs` と同じ形式である（`--key <キー>` と、`--paths`・`--paths-json`・`--paths-file`・`--dirs`・`--dirs-json`・`--exclude`・`--exclude-json` のいずれか。単体モードは `--all`、または引数なし）
- 受け取った引数を、解釈せずにそのまま script へ渡す。引数の検証は script が行い、反する指定は拒否される
- 親の文脈（作業の指示・差分・文書の本文など）を引数へ足さない

## 手順

### 1. 付与計画を作る

何も書き込まずに、付与計画を作る。

```bash
uv run --locked "${CLAUDE_SKILL_DIR}/scripts/embed_dlid.py" plan --project-root "${CLAUDE_PROJECT_DIR}" {受け取った対象指定の引数}
```

- 標準出力の JSON を読む。`needs_origin` が偽なら、手順 3 へ進む
- 終了コードが 0 以外のときは、標準出力の `errors` を利用者へ報告して終える。対象指定を直して再実行できる
- `problems`（存在しない・Markdown でない指定）と `warnings` があれば、あわせて報告する

### 2. 重複する DLID の原本を確定する（`needs_origin` が真のときだけ）

`duplicates` のうち `needs_origin` が真のものごとに、AskUserQuestion で原本を確定してもらう。

- 選択肢は、その重複の `candidates`（管理状態に記録されたパスと一致する箇所）とする。`candidates` が空なら、`locations` のすべてとする。各選択肢には、パス・種別（document は文書 ID、section は見出し）・見出しの行・見出しのテキストを示す
- 選択肢が 4 つを超えるときは、先頭の 3 つと、パスと行を利用者が入力できる選択肢にする
- 利用者が選んだ箇所の `origin_args`（4 つの値）を控える。値を作り直さない
- 利用者が原本を確定せずに終えたときは、何も書き込まずに終える。そのことを報告する

### 3. 書き込む

```bash
uv run --locked "${CLAUDE_SKILL_DIR}/scripts/embed_dlid.py" apply --project-root "${CLAUDE_PROJECT_DIR}" {受け取った対象指定の引数} --origin {origin_args の 4 つの値}
```

- `--origin` は、手順 2 で確定した重複ごとに 1 回ずつ足す。手順 2 を行わなかったときは足さない
- script が、文書ごとに書き込み、再解析して差分が DLID だけであることを検証する。DLID 以外の差分があれば、その文書への書き込みを取り消す
- 終了コードが 0 のときは、全対象に書き込み、検証した。手順 4 へ進む
- 終了コードが 3 のときは、原本の指定を求める重複が残っていて、何も書き込まれていない。標準出力の `duplicates` を使い、手順 2 からやり直す
- 終了コードが 4 のときは、書き込めなかった文書がある。検証を通って書き込んだ DLID は戻らず、発行済みである。手順 4 で、発行済みの DLID と、書き込めなかった文書を報告する
- それ以外（1）のときは、標準出力の `errors` をそのまま利用者へ報告して終える

### 4. 結果を報告する

標準出力の JSON から、次を報告する。

- 書き込んだ文書・位置・DLID（`written`。`replaced` があるものは、置き換えた旧い値も示す）
- 書き込めなかった文書ごとの、パス・問題箇所・原因（`failed`。取り消したかは `reverted`）。1 件でもあれば、この操作は失敗である。書き込めなかった文書は、原因を直してから、同じ指定でもう一度実行する。書き込み済みの DLID は既存の DLID として照合し直され、残りの文書だけが処理される
- 書き込めなかった文書が残るときは、その文書に DLID が無く、ToC に入らないことも伝える
