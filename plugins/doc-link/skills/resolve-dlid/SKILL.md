# resolve-dlid

このスキルは DLID の解決のみを行う。親が依頼している他の作業を引き継いではならない。自身を Skill ツールで呼ばない。

何も書き込まない。管理状態と、記録されたパスの文書を読むだけである。doc-link が利用者の文書へ書き込むのは DLID だけであり、このスキルは文書にも管理状態にも書き込まない。記録されたパスの外は探索しない。

## 引数

- DLID の並びだけを受け取る。ToC 識別キーは受け取らない
- 受け取った DLID を、解釈せずにそのまま script へ渡す。DLID として認識できない値は script が拒否する
- 親の文脈（作業の指示・差分・文書の本文など）を引数へ足さない

## 手順

### 1. 解決する

```bash
uv run --locked "${CLAUDE_SKILL_DIR}/scripts/resolve_dlid.py" --project-root "${CLAUDE_PROJECT_DIR}" {受け取った DLID の並び}
```

- 終了コードが 0 のときは、標準出力の JSON を読み、手順 2 へ進む。記録されたパスに無い DLID や記録の無い DLID があっても終了コードは 0 である
- 終了コードが 0 以外のときは、標準出力の `errors` をそのまま利用者へ報告して終える。管理状態を読めないときは、失敗とその原因（`kind` と対象）である。「記録が無い」と取り違えて報告しない

### 2. 結果を報告する

標準出力の `results` から、DLID ごとに次のいずれかを報告する。

- 解決済み（`status` が `resolved`）: `path`（記録されたパスで、現物の DLID と一致したもの）と、内容ハッシュ。セクション（`kind` が `section`）には `heading` と `anchor` を添える
  - `content_hash_state` が `recorded` のときは `content_hash` を報告する
  - `differs`（セクションの内容ハッシュが記録によって異なる）と `unavailable`（得られない）のときは、内容ハッシュを報告せず、その旨を報告する
- 記録されたパスに無い（`not_at_recorded_path`）: `recorded_paths` を添えて報告する。これは現在の実体パスではない。確かめられなかったので、別の場所を探さない
- 記録が無い（`no_record`）: 記録が無いと報告する

### 3. 次の作業を案内する

記録されたパスに無い DLID があるときは、`guidance` に従い、`index-docs` の実行を案内する。その文書を含む ToC を再構築すると、記録が現物に合わせて更新される。案内するだけで、`index-docs` をこのスキルから実行しない。

## 参照を書くときの手順（プロジェクト管理 AI 向け）

プロジェクト管理 AI が参照を書くときは、次の順で行う。

1. 参照先を含む ToC 識別キーで `check-toc` を実行する。古ければ `index-docs` を実行する
2. `resolve-dlid` で、参照先の DLID のパスと内容ハッシュを得る
3. リファレンスリンクの定義の title に、`"<内容ハッシュ> DLID-…"` を書く
4. 参照の行を足したときは、参照元の本文が変わるので、`index-docs` を実行する
5. title の内容ハッシュだけを書き換えたときは、参照元の内容ハッシュが変わらないので、`index-docs` は要らない

書くのはプロジェクト管理 AI であり、`resolve-dlid` ではない。
